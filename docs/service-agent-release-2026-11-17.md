# 통합 비서 1차 구현 기록

기준: 2026-11-17, 로컬 main d69e948에서 작업. 코드 구현과 운영 사용 가능 상태를 구분한다.

## 목표와 이번 범위

채팅을 코칭/비서 두 경로로 나누고 기존 시스템의 자료·기록·일정·코칭 경로를 연결하는 첫 단계다. 코칭 엔진을 새로 만들거나 추천 모델/지침을 바꾸지 않는다. 모든 기능의 자연어 CRUD와 서버 소유의 장기 작업 하네스는 아직 완료하지 않았다.

## 구현한 흐름

1. 사용자가 텍스트/자료를 보낸다. 요청은 계정·채팅 세대에 묶인 큐로 직렬 처리한다.
2. 파일만 있으면 기존 자료 수신 파이프라인으로 보낸다. 분류기나 코칭 모델을 호출하지 않고 이해도/학습 완료도 만들지 않는다. 이전 채팅의 코칭 요청을 파일 업로드만으로 재개하지 않는다.
3. 텍스트와 파일이 함께 있으면 신규 AI 동의 후 파일 등록 의도를 먼저 해석한다. 등록하지 말라는 요청에는 업로드를 실행하지 않는다. 현재 저장 없이 PDF를 읽어 답하는 기능은 미지원으로 안내한다.
4. 자료 등록이 필요하면 기존 파일 파이프라인을 기다린다. 일부 실패는 결과를 보존하고 후속 텍스트 작업을 중단한다. 성공 후 최신 DB를 동기화·조회하고 본 요청을 다시 준비한다.
5. `service-agent`가 인증·기능 플래그·동의·입력 크기·일일 한도를 검사한다. 분류 모델은 assistant/coaching만 반환한다.
6. 비서 모델에는 `read_service_data`와 `prepare_workflow`만 제공한다. 읽기는 서버가 고정한 본인 DB 조회뿐이며, 준비 도구는 쓰기 권한이 없다. 최대 6회 비서 호출, 같은 요청의 중복 읽기는 메모리 캐시, 읽기 실패는 빈 결과로 숨기지 않는다.
7. 학습 관측은 기존 `chat-record` → 기존 주제/문항 RPC·회차 동기화로 저장한다. 척도와 취소/수정 경로를 유지한다. 기록 실패·미확인·일부 누락이 있으면 후속 작업을 허용하지 않는다.
8. 신규 과제/시험/퀴즈/개인 일정은 제목·과목·시간·내용 미리보기 후 버튼으로 승인한다. 사용자 JWT/RLS를 사용하는 기존 calendar_events 경로에 추가한다. 임의 수정/삭제/upsert는 없다. 카드의 고정 UUID로 네트워크 재시도 중복을 막고 이미 변경된 일정은 덮어쓰지 않는다.
9. 일정은 원본 DB에서 코칭·수업·대시보드로 연결된다. 시간표에도 원본을 읽어 표시한다. 기존 브라우저 월간 일정은 중복 표시하지 않고 원격 일정을 브라우저 저장에 복제하지 않는다. 과목별 원격 일정은 과목 관리 화면으로 연결하며 일반 개인 원격 일정의 편집 UI는 후속이다.
10. 코칭 요청은 기존 `CoachingRequestPanel`에 목표·요청 유형·명시한 하루 학습시간·기간·일회성 요청을 전달한다. 사용자가 조건을 확인해 기존 자료 준비/코칭 제안/승인 절차를 수행한다. 비서 모델이 별도 계획을 생성하지 않는다.

## 보호 경계

- 새 AI 동의를 기존 기록 전용 동의와 분리한다. 동의를 받았다는 이유로 모든 데이터를 전송하지 않으며 필요한 DB 표의 제한된 열/행만 읽는다.
- 서비스/분류 모델 기본값은 gpt-6.1-terra, 기존 코칭 설정과 독립이다. 실제 계정 접근·분류 품질은 아직 검증하지 않았다.
- `store:false`, 원문 로그/신규 원문 DB 저장 없음. 업무 필드(과제명·범위 등)와 일회성 맥락을 분리하는 지침 및 기존 개인화 계약 유지.
- 자기평가와 채점 결과를 별도 조회한다. PDF는 비서에 메타데이터만 제공하므로 내용을 읽었다고 답하지 않도록 지침을 제한한다.
- 자료/DB/대화 내용은 지침으로 취급하지 않는다. 허용되지 않은 함수명/조회 도메인·타 목표 ID·잘못된 날짜/시간·미완료 모델 응답은 거절한다.
- 새 채팅·계정 변경·취소·15분 경과 시 기존 작업 카드는 무효다. 학습 기록이 취소/수정 중이면 후속 작업을 다시 확인한다.
- 기능 플래그 OFF에서는 기존 기록 전용 채팅 경로를 유지한다. 서버 오류를 기록 해석기로 자동 우회해 다른 부작용을 만들지 않는다.

## 아직 구현하지 않은 전체 설계 항목

- 서버에 저장되는 agent_runs/actions, 승인 티켓/RPC, 여러 기기 동시 작업·취소·재시도 원장. 현재 확인 카드는 탭 메모리이며 새로고침하면 사라진다. DB에 이미 저장된 업무 기록은 남는다.
- 비서의 실제 쓰기를 모두 Edge 도구로 옮기는 작업. 이번 일정 추가는 기존 인증/RLS 브라우저 저장 경로이고, 승인 만료·버전 확인의 서버 강제 구현은 후속이다.
- 기존 일정/계획/목표의 자연어 수정·삭제, 반복 일정, 수업 회차 추가, 목표 생성, 자료 이동·일괄 재분류 등 모든 기능의 도구화.
- 텍스트로 지정한 자료 대상 과목/형식을 파일 파이프라인의 확정 입력으로 연결하고 미리보기하는 작업. 지금은 기존 파일 내용 기반 분류/사용자 수정 UI를 재사용한다. 잘못 분류된 파일은 사용자 확인이 필요하다.
- 파일 버전별 중복 등록 억제/혼합 PDF 분할의 완전한 통합, 브라우저를 닫아도 계속되는 자료 처리, 유효한 이전 코칭 자료 대기 요청의 서버 재개.
- 실제 PDF 근거를 읽는 자료 설명 도구. 현재 비서는 파일 메타데이터 조회만 가능하다.
- 코칭의 필수 시간창/시험 입력을 대화만으로 완성하는 후속 어댑터. 지금은 기존 확인 화면이 남는다. 입력하지 않은 순공시간은 0으로 두어 확인을 요구한다. 기간 누락은 기존 기본 기간을 확인 화면에 표시한다. 14일 초과 실행 구간을 몰래 자르지 않는다.
- 일정을 배치하지 않는 자유 학습 진단 계약, 3주 전망 자연어 연결, 실제 수행기록·승인형 재계획 고도화.

## 검증 구분

로컬 자동 계약/DB/브라우저 테스트는 고정 모델 응답과 테스트 DB를 사용한다. 실제 API 품질이나 운영 데이터 검증으로 해석하면 안 된다. 최신 시험 결과는 작업 완료 보고와 실행 로그를 따른다.

2026-11-17 로컬 검증 결과:

- 전체 Node/DB 테스트 250개 통과(실패 0), TypeScript 및 ESLint 통과.
- Supabase 함수 19개 타입 검사 및 webpack 프로덕션 빌드(19개 페이지) 통과.
- 통합 기능 ON: PC/모바일에서 동의, 승인 전 무저장, 일정 승인/시간표 표시, 기존 코칭 조건 전달, 저장 거절 첨부, 파일 단독 수신, 새 채팅 초기화, 가로 넘침/브라우저 오류 없음 확인. 외부 HTTP는 테스트 응답으로 대체했다.
- 통합 기능 OFF: 기존 기록 전용 동의/거절, 새 채팅 초기화, 기존 코칭 창을 PC/모바일에서 확인했다. 기존 동의 버튼 문구도 유지한다.
- 임시 가상 DB 서버는 종료했다. 로컬 미리보기는 기존 환경 설정과 통합 기능 OFF로 실행한다. 운영 연결 완료로 해석하지 않는다.
- 실제 Terra 모델 호출, 운영 DB 쓰기, 새 migration, 배포, 커밋/푸시는 수행하지 않았다.

새 시험 파일: `tests/service-agent.test.mjs`, `tests/service-agent-db.test.mjs`, `tests/service-agent.browser.mjs`.
서버 타입 검사: `npx deno task --config supabase/deno.json check`.
브라우저 시험은 Playwright와 임시 테스트 서버를 사용하며 실제 사용자 DB/API를 호출하지 않는다.

## 운영 적용 전 순서

1. 최신 Git/운영 서버와 DB 계약을 대조한다. 이전 원격 전용 migration 0038을 확인하기 전 새 번호를 만들지 않는다. 이번 변경은 새 migration이 없다.
2. 테스트 계정에서 기존 chat-record/파일 수신/코칭과 신규 service-agent를 배포·검증한다. 운영 배포는 현재 작업에서 수행하지 않았다.
3. Supabase 비밀 설정: `SERVICE_AGENT_ENABLED=true`, `SERVICE_ROUTER_MODEL=gpt-6.1-terra`, `SERVICE_ASSISTANT_MODEL=gpt-6.1-terra`. OPENAI_API_KEY는 기존 서버 비밀 설정을 사용하며 브라우저에 넣지 않는다.
4. 웹 빌드 설정의 `NEXT_PUBLIC_SERVICE_AGENT_ENABLED=true`로 통합 경로를 켠다. 기존 `NEXT_PUBLIC_COACHING_ENABLED` 등은 그대로 필요하다. 서버 배포 전에 웹만 켜면 통합 요청은 오류로 종료한다.
5. 한국어 부정·생략·모호함·복합 요청·자료만 입력·일회성 맥락을 실제 모델로 평가한다. 예산을 먼저 정하고 정확도/부작용/토큰/지연을 측정한다. 이번에는 유료 평가하지 않았다.
6. 서버 승인/작업 원장과 미지원 도구를 차례로 확장한 뒤 전체 서비스 자동화를 완료한다. 문제가 있으면 웹/서버 플래그를 끄며 기존 코칭/기록 화면을 유지한다.

## 기존 과제 유지

Drive 실제 원본/전체 동기화 대조, 실제 코칭 품질 비교, 실행 기록 UX, 승인형 재계획, 개인 학습시간/분량 보정은 계속 남아 있다. 이번 통합은 이 기반을 교체하지 않는다. PDF 구조도/Word 갱신·커밋/푸시·운영 배포는 이번 코드 구현과 별개다.
