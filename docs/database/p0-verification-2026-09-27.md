# P0 검증 결과 및 후속 작업

검증일: 2026-09-27. 코드 브랜치: `DB-ver`. Supabase: `beqdvsfwybuisylxbqko`.

## 판정

P0 DB 스키마는 원격에 적용되어 있고, 확인한 제약조건 및 접근 제어 검증을 통과했다.
사이트 동기화 코드는 별도 결함이 있어 이번에 수정하고 통합 테스트를 추가했다.
실제 계정의 브라우저 데이터 이관과 운영 환경의 로그인 흐름까지 검증 완료한 상태는 아니다.
에이전트를 운영 배포하기 전에 아래 실제 계정 검증과 수집 경로 보완이 필요하다.

Git 브랜치는 DB를 분리하지 않는다. 이번 원격 검증은 기존 사이트와 공유하는 프로젝트에 읽기 전용으로 수행했다.
이번 검증 중 원격 마이그레이션 적용, 테스트 데이터 삽입, 운영 데이터 수정, 커밋 및 푸시는 하지 않았다.

## 발견한 문제와 수정

| 문제 | 수정 |
| --- | --- |
| 저장 시 평면 metadata, 복원/변경 반영 시 legacy_record를 기대 | 저장 형식 통일, 이전 평면 형식도 읽기 지원 |
| 복원용 목록에서 분류 대신 잘못된 배열 항목 사용 | 테이블/저장소 키 기반 매칭으로 정리 |
| 삭제 쿼리가 여러 테이블에 없는 컬럼을 조회 | 실제 테이블 컬럼에 맞는 조회 및 상태 변경 |
| 수업·주간·월간 복사본이 중복 계획으로 저장될 수 있음 | 수업/주간 공유 계획 하나와 월간 표시용 복사본으로 연결 |
| 과목 미지정 self 계획 누락 | 개인 학습 목표에 연결 |
| 다른 기기의 행이 로컬에 없다는 이유로 삭제될 수 있음 | 해당 브라우저에서 명시적으로 바꾼 ID에만 삭제 적용 |
| 취소/삭제한 데이터가 오래된 브라우저에서 다시 나타날 수 있음 | 아카이브·취소·삭제 표시를 읽어 로컬 복원에 반영 |
| 네트워크 실패 후 변경분 유실 및 동기화 작업 중첩 | 계정별 영속 대기열과 직렬 처리, 초기화·온라인 복귀 시 재시도 |
| 계정 전환 중 비동기 결과가 새 계정에 쓰일 수 있음 | 요청 전후 계정/작업 세대 확인 |
| 원격 조회 기본 행 수 제한, time 값에 초가 붙어 UI와 불일치 | 페이지 조회, HH:mm 복원 |
| 기한 표시가 가용 시간을 막는 일정으로 저장됨 | 해당 자동 기한 이벤트를 nonblocking deadline으로 저장 |
| 수업 진도 속도에 임의 숫자, 완료 시점에 생성일 사용 | 속도 수치는 NULL 유지, 불명확한 완료 시각은 추정 표시 |
| 인증 갱신 때마다 화면과 전체 초기 동기화 재시작 | 같은 검증 계정은 반복 초기화 생략 |

이관 전 원본은 해당 계정의 브라우저 저장소 `unilink:p0-before-import-v1`에 한 번 보관한다.
이는 브라우저 저장소를 지우면 사라지는 보조 사본이며 DB 백업은 아니다.

## 수행한 테스트

`npm test`: 총 49개 통과, 실패 0개. 기존 테스트와 아래 신규 통합 시나리오를 포함한다.

1. 첫 적재, 재실행 시 중복 방지, 주말 시간, 개인 계획, 목표 기한 연결.
2. 빈 브라우저 저장소로 과목·목표·계획·반복 일정 복원.
3. 여러 저장소를 연속 수정하고 완료 상태 반영.
4. 전송 실패 후 재초기화 시 미전송 변경분 우선 재시도.
5. 수업 시간 변경 시 이전 시간 슬롯 제거.
6. 주간 계획 삭제 시 공유 계획과 수업·월간 표시 일치.
7. 삭제 처리와 오래된 캐시에서 삭제 항목 재등장 방지.
8. 501개 목표를 두 페이지 이상에서 모두 복원.
9. 불완전한 로컬 목록이 다른 기기 데이터를 아카이브하지 않음.
10. 조회 중 계정 전환 시 새 계정 캐시에 이전 계정 데이터가 들어가지 않음.

기존 PostgreSQL 테스트는 사용자별 RLS, 타인 소유 FK 거부, 토픽 계층/순환 금지,
시간/기간/단위/JSON 버전 제약, 계획 승인·개정·중복키, 계정 삭제 참조 처리 등을 검증한다.

변경 파일 ESLint, `tsc --noEmit`, `npm run build`도 통과했다.
통합 테스트는 실제 TypeScript 저장소 모듈과 실제 마이그레이션을 사용한다.
브라우저 API 및 Supabase HTTP 전송은 테스트용으로 대체하므로 실제 Auth 토큰, PostgREST 네트워크,
React 인증 수명주기 전체를 검증했다는 뜻은 아니다.

## 아직 확인하지 못한 것

- 로컬에는 `.env.local.example`만 있고 실제 Supabase URL·공개키 환경변수도 미설정이다.
- 실제 사용자 로그인, 최초 이관, 다른 브라우저 재로그인, 운영 HTTP를 통한 RLS/토큰 갱신은 미검증이다.
- 여러 테이블의 저장은 하나의 DB 트랜잭션이 아니다. 부분 실패 시 대기열이 재시도하지만 AI 계획 승인 API에는 원자적 처리가 필요하다.
- 서로 다른 기기에서 같은 항목을 동시에 고쳤을 때의 충돌 해결 및 실시간 구독은 미구현이다.
- 실제 학습 실행 시간/결과를 `study_sessions`에 쌓는 화면 연결, 토픽 입력·연결, 선호 설정 UI는 아직 구현 범위가 부족하다.
- 새로 만든 P0 UUID와 기존 노트·Drive 자료의 연결은 후속 자료 레지스트리/매핑 설계가 필요하다.
- 출처 표시된 기본 학습 시간 30분·기본 방법은 확정 목표나 실제 수행 기록으로 사용하면 안 된다.
