# 코칭 우선 작업 1~3 구현·검증 보고

기준: 2026-11-09, main의 `a98576e` 이후 작업. 사용자 요청에 따라 영향 검토와 안내 보완을 포함해 커밋·푸시 대상으로 정리했다. **운영 DB 적용·운영 코칭 서버 배포는 별도이며 이번 작업에서 하지 않는다.** 실제 커밋·푸시 결과는 Git 이력으로 확인한다.

## 1. 이해도 반영 효과 검증

주제 이해도는 이미 연결돼 있으므로 새 이해도 입력 UI를 만들지 않았다. 기존 자기평가 1~5의 의미를 모델 입력에 명시하고 문제은행 단계·채점 결과와 구분했다. 입력 버전은 `coaching-evidence-v4`, 지침은 `understanding-evidence-v15`다. 모델·추론 강도·출력 상한·일정 검증·승인 계약은 유지했다.

### 검증 방법

- SQL LEFT JOIN, 조건부확률/베이즈 정리, 개인 파이썬 CSV 처리의 합성 사례를 만들었다.
- 같은 과목 안에서는 자료·주제·진도·날짜·목표·60분 시간 예산을 고정하고 자기평가 값만 1/5 또는 5/5로 바꿨다. 양쪽을 2회씩 생성해 총 12회 실제 `gpt-6.1-sol` 호출했다.
- 미평가(null)는 자동 입력 대조 테스트에 포함했지만 이번 유료 생성에는 포함하지 않았다. 상충/오래된 채점 근거와 운영 사용자 평가는 후속이다.
- DB에서 모델 입력까지의 연결은 실제 PostgreSQL 호환 테스트 DB로, 실제 생성 비교는 고정 합성 context로 검증했다. 운영 DB의 사용자 기록을 읽거나 수정하지 않았다.
- API 키는 출력·파일 저장하지 않았고, JWT 서명 검증 및 고정 요청 해시 제한이 있는 서비스 전용 임시 평가 함수만 사용한 뒤 삭제를 확인했다. 정답처럼 보이도록 결과를 재작성하거나 실패 출력을 숨기지 않았다.

### 관측 결과

| 사례 | 자기평가 1/5, 각 2회 | 자기평가 5/5, 각 2회 |
| --- | --- | --- |
| SQL | 개념/행 추적 20분 + 적용 40분 | 새 쿼리 적용 35분 + 반례/설명 25분 |
| 확률론 | 확률 방향·빈도표 25분 + 계산/해석 35분 | 새 검사 사례 35분 + 조건 변경 비교 25분 |
| 파이썬 개인 학습 | 작은 CSV 예측·개념 15~20분 + 구현 40~45분 | 직접 구현 40분 + 검증/재실행 20분 |

12/12 생성 완료, 보정 전·후 일정 검증 모두 통과했다. 높은 이해도에 무조건 시간을 덜 주지 않고, 동일한 총 시간에서 시작 활동과 배분이 달라졌다. 자기평가를 객관적 숙달로 단정하거나 합성 자료를 실제 업로드 PDF로 가장하지 않았다.

**한계:** 파이썬의 낮은 이해도 응답에도 nullable 정수형 변환이나 처리 방식 비교가 추가돼 부담이 커질 수 있었다. SQL의 반례도 낮음/높음 모두에 등장했다. 따라서 이해도가 입력에 도달하고 추천 차이를 만드는 것은 확인했지만, 모든 과업의 난이도 조절이 최적이라고 판정하지 않는다. 개발 보조 AI의 비블라인드 정성 검토이며 전문가 평가·학습 효과 입증·기존 버전 대비 향상률 측정이 아니다.

실제 응답은 `docs/evaluations/coaching-understanding-2026-11-09.json`에 보존한다. 관측 합계: 입력 34,192토큰, 출력 8,375토큰, 총 42,567토큰. 평균 왕복 약 10.51초. 새 입력·문제은행의 일반적인 비용이나 이전 버전 대비 비용 차이를 측정한 것은 아니다.

`COACHING_EVAL_SUITE=understanding`, `COACHING_EVAL_OUTPUT=<저장 폴더>`를 환경 변수로 설정하고 `node --experimental-strip-types scripts/evaluation/coaching-quality.mjs`를 실행하면 무료로 12개 요청을 캡처한다. 실제 생성은 안전하게 설정한 `OPENAI_API_KEY`와 `--live`가 필요하며 12회 비용이 발생한다. ## 2. 과목 수준·자료 근거 전달 보완

- 기존 분석 아티팩트를 재사용하고 PDF 분석/검색 캐시 버전은 바꾸지 않았다.
- 주제 상태에 연결된 노트 ID·페이지를 자료 선택의 보조 근거로 사용한다. 요청 범위의 단어 관련성이 우선이며, 동점일 때 연결 페이지를 활용한다. 다른 노트의 같은 페이지는 매칭하지 않고 미확정 주제의 연결 정보는 제외한다.
- 긴 주차별 계획 때문에 평가·과제/시험 일시·선수지식·학습 목표가 상위 30개 사실에서 밀리는 문제를 보완했다. 이 우선순위는 자료 선택용이며 공부 시간/방법을 강제하는 정책이 아니다.
- 선택된 단원에 아티팩트·페이지·제목 기반 `unit_ref`와 겹치는 문서 종류를 남긴다. 원본 PDF의 영구 단원 ID가 아니라 해당 분석 아티팩트 내 참조다.
- 요구 깊이·선수지식은 과목 내용의 분석 근거이며 개인 숙달이나 측정된 타인의 평균 공부시간이 아님을 명시했다.

노트/페이지 일치, 현재 요청 우선, 자료 불변, 평가 사실 보존, 잘림 표시, 기존 캐시 재사용 테스트를 통과했다. **실제 사용자의 원본 강의계획서·강의노트와 추출 정확도를 대조한 것은 아니다.** 실제 문서 표본에서 수식·표·요구 수준이 맞는지 확인하는 일은 남아 있다. 의미 검색이나 동의어 처리 엔진이 새로 완성된 것도 아니다.

## 3. 문제은행 이해도 연결

### 연결과 화면

문제은행 화면에 `코칭 학습 목표`, `이 문제은행 전체의 공통 주제 (선택)`, 저장/해제를 추가했다. 과목명으로 자동 합치지 않는다. 한 문제은행 과목은 하나의 학습 목표에 연결되고, 선택한 공통 주제는 그 문제은행 전체에 적용된다. 여러 주제가 섞였으면 주제를 지정하지 않고 목표에만 연결한다. 개별 문제마다 서로 다른 주제를 지정하는 기능은 이번 범위가 아니다.

새 `problem_bank_coaching_links`는 원래 문제와 단계 값을 수정하지 않는다. 같은 은행의 새 업로드 문제도 이 연결을 통해 조회된다. 목표 삭제는 연결만 제거하고 문제은행 원본은 보존한다. 주제 삭제는 공통 주제 연결을 해제한다.

### 입력과 의미

- `coaching_problem_bank_states` 뷰에서 본인의 선택 목표에 연결된 기록만 읽는다. 목표별 최신 20개, 초과 여부를 모델에 표시한다.
- 모델에는 문제 ID·라벨·단계와 의미·관측 시점을 전달한다. 문제 라벨은 문항 본문이 아니므로 문제 번호만 보고 내용을 진단하지 않게 했다.
- 0=미학습, 1=읽음, 2=답안 보고 풂, 3=답안 이해, 4=자력 시도, 5=사용자가 표시한 마스터 단계다. 검증된 정답률이나 주제 자기평가 1~5로 자동 환산하지 않는다.
- 기존 기본값 0은 사용자가 직접 0으로 평가했는지 구분되지 않는다. 이를 취약 진단으로 단정하지 않는다. 새 `level_recorded_at`은 사용자가 단계 값을 저장할 때 DB 트리거로 기록하며, 기존 기록의 과거 관측 시각을 만들어 채우지 않았다.
- 복합 외래키와 RLS로 다른 사용자의 은행/목표/주제 연결을 막는다. 미확정·다른 목표의 주제는 모델에서 임의 진단하지 않도록 제외한다.
- 마이그레이션 전에는 신규 기능 상태를 `schema_unavailable`로 표시한다. 다른 DB 장애를 정상적인 빈 기록으로 숨기지 않는다. 연결이나 기록이 없어도 기존 주제 이해도로 추천할 수 있다.

## 수정 영향 재검토

이번 재검토는 코드 차이와 앞서 수행한 시험 결과를 확인한 것이며, 운영 데이터나 배포 상태를 새로 검증한 것은 아니다.

- 확인된 효과: 같은 시간 예산에서 자기 이해도에 따라 시작 활동과 배분이 달라졌다. 기존 버전보다 얼마나 좋아졌는지나 교육 성과 향상률은 이번 비교로 알 수 없다. 문제은행의 추가 정보 자체가 추천 품질을 얼마나 높이는지도 별도 실제 생성 비교가 필요하다.
- 변경 범위: 코칭 입력/지침과 입력 스냅샷의 추가 필드, 자료 선택 순서, 문제은행 연결 화면 및 신규 DB 객체가 바뀐다. 이미 승인된 계획은 새 지침으로 자동 재작성하지 않는다.
- 유지 범위: 최종 계획 출력과 승인 RPC 계약, 시간대·충돌·휴식·기존 계획 보존 검사, 모델 선택, PDF/검색 캐시 키, 기존 업로드/이해도 단계 선택 흐름은 변경하지 않았다. 회귀 테스트 통과는 모든 운영 상황에서 오류가 없다는 보장은 아니다.
- 새 장애 의존성: 문제은행 조회는 목표당 한 번 추가된다. 테이블 미적용 오류만 명시적인 미사용 상태로 처리하고, 권한/네트워크/기타 DB 오류는 503으로 전체 코칭 생성을 중단한다. 가짜 빈 이력으로 진행하지 않는 장점이 있으나 부가 기능 장애가 전체 추천 가용성에 영향을 준다. 운영 전 이 동작을 유지할지, 사용자에게 누락을 알리는 제한 모드를 둘지 결정·검증해야 한다.
- 전송 범위 변화: 명시적으로 연결한 문제은행의 문제 라벨·단계·시점이 최종 코칭 요청을 통해 OpenAI에 전달된다. 계정 전체 문제은행이나 문항 PDF 전체를 새로 전송하는 것은 아니다. 현재 개인정보 페이지의 PDF 분석/검색 안내만으로 새 코칭 전송 범위를 충분히 설명하는지 점검하고, 연결/코칭 진입 안내 및 실제 전송 내용을 일치시키는 보완이 필요하다. 법적 적합성을 검증한 것은 아니다.
- UI의 추가 동작: 연결 선택을 준비하며 기존 flushP0Changes를 호출해 대기 중인 학습 데이터 동기화를 수행한다. 새로운 학습 목표를 자동 생성하거나 과목명을 자동 연결하는 기능은 아니다. 문제은행 전체에 공통 주제가 적용되므로 혼합 주제 은행에 하나를 강제 지정하지 않아야 한다.
- 비용/지연: 단계 설명과 문제은행 기록 때문에 입력량 및 DB 조회가 늘 수 있다. 목표별 최신 20개 제한은 전체 이력 보장이 아니며 미평가 기본값이 많은 은행에서는 관측 이력이 밀릴 수 있다. 초과 상태는 전달하지만 일반적인 비용 증가율이나 속도 개선은 측정하지 않았다.

### 커밋 전 영향 검토 결정

- 조회 오류는 기존 fail-closed 방식을 유지한다. DB 미적용은 명시적 미사용 상태로 처리하고, 다른 권한·통신 오류는 코칭을 중단해 근거 누락을 숨기지 않는다. 전체 추천 가용성과의 절충이며 제한 모드는 구현했다고 주장하지 않는다.
- 연결 화면과 개인정보 안내에 실제 최종 코칭 전송 범위 및 연결 해제 후 이전 코칭 기록이 남는 점을 명시했다. 별도의 PDF 분석/검색 동의 흐름은 유지한다. 이 보완을 법적 적합성 인증으로 표현하지 않는다.
- 운영 DB·서버 배포는 하지 않는다. 0029→서버→프런트의 적용 순서를 유지하고 실제 계정 통합 확인 및 원본 PDF 대조를 릴리스 후속으로 남긴다.
