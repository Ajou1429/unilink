# Drive 폴더 경로·전체 동기화 수정

## 원인과 수정

- 기존 탐색은 선택한 폴더부터 경로를 만들었다. `GoodNotes/품질공학`을 선택하면 `품질공학`만 저장돼 기존 트리에서 분리됐다. 서버의 실제 부모 폴더 ID를 거슬러 공통 경로를 만들고 수동 동기화·웹훅·빈 폴더 표시에 같은 경로를 사용한다. 표시 경로를 유지해도 선택하지 않은 형제 폴더의 파일을 가져오는 것은 아니다.
- 화면도 별도 탐색으로 선택 폴더를 최상위에 만들었다. 이제 서버의 경로 포함 폴더 트리를 사용한다.
- 기존 자동 동기화 대상의 하위 폴더만 수동 갱신하면 대상 자체가 하위 폴더로 바뀌었다. 선택한 대상이 전부 기존 대상 안에 있으면 기존 자동 동기화 범위를 유지한다. 다른 독립 폴더를 선택하면 새 대상으로 변경한다. OAuth 재연결의 기존 폴더 초기화 정책은 계정 혼입 방지를 위해 유지한다.
- 상위 폴더 전체 동기화는 기존에도 재귀/페이지 탐색이었다. 해당 경로를 유지하고 PDF 목록 조회와 노트 저장을 각각 최대 4개씩 병렬 처리하여 순차 왕복 대기를 줄였다. 전체 탐색/저장 성공 후에만 성공 응답과 폴더 설정을 저장한다. 중간 실패는 일부 반영 가능성을 표시하며 재시도는 같은 파일 ID의 기존 노트를 갱신한다.
- 목록을 읽기만 해도 현재 시각을 마지막 확인으로 표시했다. 이를 제거하고 이 브라우저·로그인 사용자별 마지막 수동 성공만 저장한다. 다른 기기/웹훅의 성공 시각은 이 표시의 대상이 아니다.
- 인증 만료는 `reconnect_required`로 저장·안내하며 성공 시각은 바꾸지 않는다. 일반 오류를 토큰 만료로 단정하지 않는다.
- 노트 버전이 갱신되면 열린 PDF 미리보기도 다시 읽는다. 기존 분류·주제·문제은행을 삭제하지 않는다.

## 적용과 복구

사용자 요청으로 Drive 동기화·과목 PDF 수정을 함께 main 커밋·푸시한다. 실제 완료 커밋과 웹 자동 배포는 Git 이력 및 작업 완료 보고를 따른다. Supabase 서버 운영 배포는 이번 푸시에 포함하지 않는다. 새 DB 마이그레이션은 없다. 운영 반영에는 공통 코드를 포함한 `drive-sync`, `drive-folders`, `drive-webhook`, `drive-file` 배포가 필요하다. 새 웹의 폴더 경로 조회는 새 `drive-folders` 응답이 필요하므로 웹 배포만으로 전체 적용이 완료되지는 않는다.

반영 후 같은 Google 계정을 연결하고 `GoodNotes` 상위 폴더를 선택해 전체 동기화를 한 번 성공시키면, 해당 파일들의 잘린 경로가 실제 경로로 복구된다. 이름이 아닌 파일 ID로 갱신하고 분류를 보존한다. 삭제된 파일 정리나 다른 계정으로 이동한 파일 복구는 이번 범위가 아니다.

## 내 수업 PDF 후속 보완

- 직접 저장한 두 페이지 PDF는 변경 전에도 PC/모바일에서 정상 렌더링됐다. 실제 사용자 계정의 실패 원인은 아직 확정하지 않았다.
- 과목별 노트 조회 실패를 빈 목록으로 숨기지 않고 오류·재시도를 제공한다. 과목 이동 또는 새로운 조회 뒤 늦게 도착한 옛 응답은 제외한다. 노트 재조회는 작성 중인 수업 노트 입력을 초기화하지 않는다.
- 폴더의 노트 수는 하위 폴더를 포함한다. 기존 분류 ID를 과목 이름만으로 임의 재연결하지 않는다.
- 공용 미리보기의 이전 오류/URL을 새 요청 시작 때 초기화한다. 로딩·원본 누락·파일 접근 실패를 표시하고 재시도 버튼을 제공한다. Drive 인증 만료 시 `drive-file`이 409/reconnect_required를 전달하며 미리보기에서 다시 연결할 수 있다. 재인증 성공 자체는 PDF 동기화 완료가 아니다.
- 열린 노트 버전 변경 때 PDF를 다시 읽고 해제된 이전 Blob URL을 계속 표시하지 않는다. 모든 과목/나의 노트에서 같은 공용 뷰어를 사용한다.
- 추가 운영 배포 대상은 `drive-file`이다. DB 변경은 없다. 로컬 빌드 및 Node 204개/서버 12개 통과, PC·모바일의 PDF 두 페이지/캔버스 실제 픽셀/원본 누락 안내를 확인했다. 실제 Google PDF와 signed URL의 운영 왕복은 별도다.

## 검증과 한계

- 검증 결과: Node 204개, 서버 시험 12개(Drive 신규 2개 포함), 서버 함수 18개 타입 검사, 웹 타입·경고 0개 린트·정적 빌드 통과. PC 1440×1000/모바일 390×844에서 새로고침만으로 성공 시각이 생기지 않음, 가로 넘침·브라우저 오류 없음을 확인했다. 브라우저는 데모 화면이고 로그인한 실제 Drive 왕복은 별도다.
- Google/DB 응답을 대체한 서버 시험에서 하위 폴더의 실제 부모 경로, 폴더/PDF 다음 페이지, 깊은 폴더 포함, 기존 감시 범위, 분류 보존, 동일 파일 재시도, 인증 만료/일반 실패를 확인한다. 실제 Google 계정의 216개 파일을 비교 완료한 것은 아니다.
- 탐색 500폴더·경로 깊이 64개 제한은 유지한다. 폴더 바로가기/Google 문서는 PDF로 가져오지 않는다. 접근 권한이 없거나 너무 큰 트리·서버 시간 제한 때문에 실패하면 전체 성공으로 처리하지 않는다.
- 아주 큰 폴더의 장기 작업·분할 재개 작업 큐는 후속이다. 전체 요청을 단일 DB 트랜잭션으로 묶은 것은 아니므로 실패 전 일부 노트는 반영될 수 있다.
- 실제 계정 확인 시 Drive PDF 수와 발견 수, 선택한 파일 수정 시각·내용, `GoodNotes/품질공학` 경로, 기존 노트 ID·분류 유지 여부를 함께 대조한다.
