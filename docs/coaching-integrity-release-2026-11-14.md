- 사용자 승인 원칙, 선택 목표 제한, 수동 계획 보호, 채점 결과와 자기평가 분리.
- 기존 수업·노트·계획·개인화 기록을 일괄 삭제·병합·점수 환산하지 않는다.
- 기존 실행 결과 수집·승인형 재계획·개인별 분량/시간 보정은 다음 개발로 유지한다.

## DB와 서버 적용 순서

**GitHub Pages 배포는 DB/Edge 배포가 아니다. 이 문서는 운영 배포 완료 보고가 아니다.**

1. 운영 마이그레이션 이력을 읽고 누락된 선행 0033~0036 및 이번 `0037_coaching_state_integrity.sql` 적용 범위를 확인한다. 기존 기록의 백업·권한·복구 절차를 확인한다.
2. DB 0037을 먼저 적용한다. 기존 관측은 `recorded_via=manual`, `voided_at=null`로 유지되며 과거 채팅 값을 추측해 삭제하지 않는다.
3. 새 공통 코드를 포함하여 `coaching-propose`, `course-knowledge`, `chat-record`를 배포한다. 새 지침은 `state-integrity-v19`, 일정 검증 정책은 `state-integrity-v7`이다. 모델 설정은 변경하지 않는다.
4. 웹 코드를 배포한다. 기존 함수가 없는 운영 DB에서는 새 채팅 주제/문항 저장·미루기가 명확한 업데이트 필요 오류로 중단된다. 이전의 안전하지 않은 저장 경로로 되돌아가지는 않는다. 따라서 **웹만 반영하면 해당 기능은 DB 적용 전까지 제한될 수 있다.**
5. 임시 계정으로 저장·수정·취소·승인·미루기·계정 격리를 확인한다. 운영 개인 데이터의 정리나 새로운 유료 모델 평가는 이번 코드 푸시와 별도다.

새 DB 객체:

- `topic_observations`: `voided_at`, `recorded_via`, `supersedes_id` 추가.
- `active_course_sessions`, `active_topic_observations`, `coaching_course_schedules` 뷰.
- 현재 이해도·개인화 이벤트·문제은행 코칭 뷰의 유효 기록/출처 반영.
- `record_chat_topic_observation`, `void_chat_topic_observation`, `revise_chat_topic_observation`.
- `set_chat_problem_levels`: 여러 문항의 버전 비교·일괄 변경.
- `postpone_coaching_plan_item`: 가용시간과 일정·시험/마감 검증을 통과한 이동만 적용.

운영 적용 미완료를 감추기 위한 자동 클라이언트 DB 생성, 서비스 키 노출, 운영 데이터 일괄 정리는 추가하지 않았다.

## 검증

- Node 자동 시험 204개 통과. 새 정합성 시험 16개 포함.
- 서버 함수 18개 Deno 타입 검사 통과, 기존 서버 시험 10개 통과. 실제 모델 응답은 고정하며 유료 API를 호출하지 않았다.
- `tsc --noEmit`, 경고 0개 린트, 정적 빌드 통과.
- 새 시험: 계정 전환 지연, 관측 순서 역전·주제 중복, 취소/수정·개인화 제외, 소유자 권한, 삭제 회차·숨긴 주제 한도, 과거 학기·명시 기간, 미입력, 문항 원자성, 승인 revision, 미루기 충돌/시험/가용시간/재시도, 파일 분류 시 단계 보존, 새 채팅 중단.
- PC 1440×1000·모바일 390×844 브라우저에서 채팅 동의/거절·새 채팅 초기화·코칭 창 열기, 가로 넘침 없음과 브라우저 오류 없음을 확인했다. 로그인한 실제 운영 통합 품질과 PostgreSQL 다중 연결 경합까지 검증한 것은 아니다.
- 최종 커밋·원격 반영 여부는 Git 이력과 작업 완료 보고로 확인한다. 운영 DB/Edge 배포와 유료 품질 평가는 수행하지 않았다.

## 남은 우선 작업

1. 운영 DB/Edge 버전 적용 및 임시 계정 통합 검증.
2. 실제 과목 2개·개인 목표 1개에서 이해도·시간·마감을 각각 바꾸는 추천 대조 평가. 이번 수정만으로 추천 품질 향상률을 수치로 주장하지 않는다.
3. 로컬 회차 동기화의 다기기 동시 편집 비교·충돌 해결과 운영 PostgreSQL 다중 연결 시험. 이번 회차 카드 보호는 현재 브라우저 상태 비교이며 전체 P0 동기화를 서버 CAS로 바꾼 것은 아니다.
4. 기존 잘못된 기록의 범위를 사용자별로 확인한 뒤 필요한 경우에만 정리. 동명 주제·원문·예전 중간값을 자동 추측하여 삭제하지 않는다.
5. 계획 실행 화면에서 실제시간·수행 범위·부분 완료·사유 수집 → 승인형 재계획 → 개인 기록 기반 보정.
