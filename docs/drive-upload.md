# Drive 업로드와 불러오기 검색

노트 추가에서 `Google Drive에도 저장하기`를 선택하거나 저장된 노트의 `Google Drive에 노트 올리기` 버튼으로 업로드한다. 노트의 내 수업·개인 학습 분류를 유지하고 Drive의 `UniLink / 대상 이름` 폴더를 자동 생성한다. 미분류 노트는 먼저 대상을 지정해야 한다. AI가 파일 내용을 추측해 분류하는 기능은 아니다.

파일 첨부 노트는 원본 파일, 파일 없이 작성한 노트는 TXT로 업로드한다. 파일 크기는 20MB 이하이다. 기존 Drive 파일은 이 업로드 작업으로 덮어쓰지 않는다. 앱 업로드 PDF가 동기화돼도 기존 제목·메모·분류를 유지한다. PDF 조회는 Drive 원본을 우선한다. TXT와 이미지의 Drive 변경 수집은 현재 PDF 전용 동기화 범위에 포함되지 않는다.

`drive_upload_jobs`에 Google 사전 생성 파일 ID를 기록하고 재시도에도 재사용한다. 원격 업로드 후 DB 저장에 실패하면 같은 파일을 연결해 중복을 방지한다. 사용자별 동시 1개와 신규 노트 24시간 최대 30개로 제한한다. 폴더는 이름보다 앱 속성의 대상 ID로 재사용한다.

## 권한 설정

Google Cloud의 OAuth 데이터 액세스 범위에 `https://www.googleapis.com/auth/drive.file`을 추가한다. 기존 전체 폴더/PDF 읽기 기능을 위해 `drive.readonly`도 유지한다. 서비스의 새 Drive 연결 요청은 두 권한을 요청한다. 기존 사용자는 Drive 연결 해제 후 다시 연결해 추가 권한을 승인해야 한다. 승인 화면에서 권한 일부만 허용하면 업로드가 실패할 수 있다.

로그인용 Google OAuth의 `openid email profile`은 그대로다. Drive 검증 제출 설명·시연에는 새 폴더·파일 생성 흐름을 포함해야 한다. `0021_drive_uploads.sql` 적용 후 `drive-upload`, `drive-folders`, `google-auth`, `drive-sync`와 `drive-webhook`을 배포한다. 공유 `driveNotes` 코드 변경은 동기화·웹훅 배포에 함께 포함한다.

## 검색

Drive 폴더 선택 창의 검색은 Drive 전체에서 폴더·PDF의 이름을 검색한다. 검색어는 Google 쿼리 문법과 분리해 이스케이프하며 100자 이하, 최대 500개 결과로 제한한다. PDF 검색 결과의 `폴더 열기`로 이동해 기존 폴더 동기화 절차를 진행한다. 원문 본문 검색과 개별 PDF만 선택한 가져오기는 포함하지 않는다.

## 검증

자동 테스트는 재시도 시 업로드 중복 방지, 분류 보존, 사용자 범위·예약 잠금, 검색 이스케이프·결과 한도를 확인한다. 실제 Google 파일 업로드와 권한 승인 흐름은 쓰기 권한을 승인한 테스트 계정에서 별도 확인해야 한다.
