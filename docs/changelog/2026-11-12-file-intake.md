# 대시보드 파일 자동 분류 (2026-11-12)

강의자료·문제은행·필기를 각자 다른 탭에서 넣고 직접 분류해야 했던 불편을 없애려고, 대시보드 한 곳에 파일을 한꺼번에 넣으면 과목과 자료 종류를 알아서 나누도록 했습니다.

> **main 반영 상태:** 사용자 요청으로 `feature/file-intake`(28190b3)를 main에 반영했습니다(GitHub Pages 자동 배포).
> **운영 DB 마이그레이션(0033·0034)과 서버 함수(`file-classify`, `drive-upload`) 배포는 아직 하지 않았습니다.** 그 전까지 실제 서비스에서는 아래처럼 동작합니다.
>
> - 파일 추가 박스는 **브라우저 분류만** 동작합니다. 과목코드·과목명이 확실한 파일은 정상 분류되고, 그 외에는 AI 호출이 실패해 미분류와 안내가 표시됩니다.
> - **강의계획서의 시간표 자동 추가·성적 반영비율 추출은 동작하지 않습니다.** AI 함수가 필요합니다. 이때 계획서 파일은 노트로만 저장됩니다.
> - **PPTX·DOCX 파일은 노트 저장이 거부됩니다.** 저장소 허용 형식(0034)이 필요합니다. PDF·이미지는 정상입니다.
> - Drive 업로드는 기존 `drive-upload` 함수가 학기·종류 값을 무시하므로 **기존 `UniLink / 과목` 폴더**로 올라갑니다.

## 결정 사항 (사용자 확인)

| 항목 | 결정 |
| --- | --- |
| 분류 범위 | 과목 + 자료 종류(강의계획서·강의자료·필기·문제은행·과제·기타). 문제은행은 문제은행으로, 나머지는 나의 노트의 해당 과목으로 |
| 확인 단계 | 바로 반영하고, 결과 목록에서 잘못된 과목·종류만 고침(시간표 추가 포함) |
| 파일 형식 | PDF, 이미지(JPG·PNG·WEBP), PPTX, DOCX. HWP는 제외 |
| Drive 폴더 | `UniLink / 학기 / 과목 / 종류` |
| 강의계획서 학기 | 계획서에 적힌 학기, 없으면 현재 학기 |
| 과목을 못 찾은 파일 | 미분류로 두고 사용자가 고름 |
| AI 전송 동의 | 처음 한 번 동의(브라우저별 저장). 거절하면 브라우저 분류만 |
| Drive 파일 분류 시점 | 앱(대시보드)을 열 때 새로 동기화된 미분류 파일을 분류 |

## 화면

- 대시보드 하단에 좌우 여백을 뺀 전체 너비의 **파일 추가** 박스를 추가했습니다.
  - 드래그 앤 드롭과 클릭 선택을 모두 지원하고, 여러 파일을 한 번에 넣을 수 있습니다.
  - 파일은 한 개씩 차례로 처리합니다.
  - 오른쪽 결과 목록의 각 행에는 처리 상태, 종류·과목 선택(바꾸면 바로 다시 분류), 들어간 곳 링크가 있고 상황에 따라 `시간표 추가`, `성적 비율`, `N문항`, `Drive` 표시가 붙습니다.
  - 결과 목록은 최근 50개까지 이 브라우저에 남습니다(`unilink:file-intake-log`).
- Drive가 연결돼 있으면 `Google Drive에도 저장`을 켤 수 있습니다.
- 위의 오늘 계획·시험·과제·오늘 수업 박스는 남는 높이를 나눠 쓰고, 내용이 넘치면 **박스 안에서 스크롤**합니다(데스크톱 기준 화면 높이에 맞춤, 모바일은 박스별 최대 높이).
- 과목 페이지 상단에 강의계획서의 **성적 반영비율**을 표시합니다.

## 처리 과정

```
파일 → ① 브라우저에서 읽기 → ② 브라우저 1차 분류 → (확실하지 않을 때만) ③ AI 분류 → ④ 반영 → (선택) ⑤ Drive 업로드
```

1. **읽기** (`src/lib/file-intake/extract.ts`). 분류에 필요한 만큼만 읽습니다.
   - PDF: 앞 2쪽 텍스트(최대 2,500자). 글자가 40자 미만이면 스캔·손글씨로 보고 **첫 쪽만** 768px JPEG로 만듭니다.
   - 이미지: 768px JPEG로 줄입니다.
   - PPTX: 앞쪽 슬라이드 텍스트. DOCX: 본문 텍스트. 라이브러리 없이 브라우저 기본 압축 해제로 읽습니다(`zip.ts`).
2. **브라우저 1차 분류** (`classify-local.ts`)
   - 과목: 과목코드(예: `ECE201`)가 맞거나, 과목명이 하나만 맞으면(서로 포함되는 이름은 더 긴 쪽) 그 과목으로 정합니다.
   - 종류: 키워드와 문항 번호 수로 판단합니다(강의계획서·문제은행·과제·강의자료).
   - **종류와 과목이 모두 확실하면 AI를 부르지 않습니다.** 토큰을 쓰지 않습니다.
3. **AI 분류** (`supabase/functions/file-classify`)
   - 위에서 줄인 텍스트나 저해상도 이미지와 사용자의 과목 목록(id·이름·코드, 최대 40개)만 보냅니다.
   - `classify`는 종류와 과목만 받습니다(출력 300토큰 제한).
   - 강의계획서는 `syllabus` 모드로 앞 3쪽(최대 6,000자)에서 과목명, 과목코드, 교수, 학점, 이수구분, 학년도·학기, 요일·시간(또는 교시 표기), 성적 반영비율을 받습니다.
   - 응답은 JSON 스키마로 고정하고, 서버가 과목 id·시간·비율을 다시 검증합니다.
   - 사용자별 24시간 200회(강의계획서 50회) 제한이 있습니다(`reserve_file_classification`).
   - 모델은 `FILE_CLASSIFY_MODEL`, 없으면 코칭 설정의 `analysis_model`, 그다음 `COACHING_MODEL` 순으로 씁니다.
4. **반영** (`pipeline.ts`)
   - **강의계획서**
     - 계획서의 학기 시간표에 같은 과목(과목코드, 없으면 과목명)이 없으면 과목을 새로 만들어 시간표에 넣습니다(요일·시간·교수·학점·이수구분).
     - 이미 있으면 시간표는 건드리지 않고 비어 있던 정보와 **성적 반영비율**만 채웁니다.
     - 계획서 파일은 그 과목의 노트(`강의계획서` 태그)로 저장합니다.
   - **문제은행**
     - PDF에서 문항 번호를 뽑아 그 과목 문제은행에 저장합니다. 3·4·7·8·9·10월은 중간고사 범위, 나머지는 기말고사 범위입니다.
     - 원본 파일도 노트로 남깁니다. 번호를 못 찾으면 안내만 하고 노트로 둡니다.
   - **그 외**: 해당 과목의 나의 노트로 저장하고, 자료 종류는 태그로 표시합니다.
   - **과목을 못 찾으면**: 미분류 노트로 두고, 결과 목록에서 과목을 고르게 합니다.
5. **Drive 업로드** (`drive-upload`): 학기·종류를 함께 보내면 `UniLink / 학기 / 과목 / 종류` 폴더를 만들어 올립니다. 기존 노트 화면의 Drive 업로드 버튼도 같은 경로를 씁니다. 학기·종류가 없는 이전 방식 호출은 기존 `UniLink / 과목` 그대로입니다.

### Google Drive에서 불러온 파일

- 기존 Drive 동기화(`drive-sync`·웹훅)가 미분류 노트로 가져온 PDF를 대상으로 합니다.
- 대시보드를 열 때 한 번에 최대 5개를 같은 1~4단계로 분류합니다. Drive에 이미 있는 파일이라 다시 업로드하지 않고, 노트의 과목·종류만 바꿉니다.
- 한 번 처리한 노트는 다시 분석하지 않습니다(`unilink:file-intake-drive-processed`).

### 결과 고치기

- 과목·종류를 바꾸면 노트 분류와 종류 태그가 바뀝니다.
- 문제은행 → 다른 종류나 다른 과목으로 바꾸면, 넣었던 문항을 지우고 새 과목 문제은행에 다시 넣습니다. 다시 넣는 것은 이번 세션에 올린 파일일 때만 가능합니다.
- 강의계획서로 만든 시간표 과목은 자동으로 지우지 않습니다. 필요하면 시간표에서 지웁니다.
- Drive에 이미 올린 파일은 원래 폴더에 남습니다.
