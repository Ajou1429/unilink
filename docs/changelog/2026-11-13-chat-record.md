# 대화로 진도·이해도 기록 (2026-11-13, `feature/chat-record` 브랜치 · main 미반영)

이전에는 수업별로 들어가 진도·이해도·난이도를 직접 골라야 했습니다. 이제 **홈 채팅에 말하면** AI가 내용을 읽고 기존 저장 경로에 바로 기록합니다.
기존 표·코칭 에이전트는 바꾸지 않았습니다. DB 변경은 AI 호출 한도에 `chat` 종류를 추가한 것(0035)뿐입니다.

## 무엇이 저장되나

| 말 예시 | 저장 위치 (기존 경로 그대로) |
| --- | --- |
| "운영체제 교착 상태 너무 어려워" | 주제별 학습 상태·이해도: `goal_topics` + `record_topic_observation` (복습 필요 · 이해도 2/5, 메모에 원문) |
| "알고리즘 오늘 수업 동적 계획법 나갔고 너무 빨랐어" | 시간표 수업 회차 진도: 진도 제목·쪽·내용 난이도·수업 빠르기 (`unilink:course-sessions` → `course_sessions` 동기화) |
| "수학2 중간 기출 5번 모르겠어" | 문제은행 문항 이해도(0~5) |

- 한 메시지에서 여러 건을 뽑습니다(예: 어려운 주제 + 수업 빠르기).
- 주제가 그 과목 목록에 없으면 사용자 주제(`source_type: user`, `metadata.origin: chat`)로 새로 만들고 카드에 `새 주제`로 표시합니다.
- "어렵다/헷갈린다/알겠다"는 AI가 상태(복습 필요·학습 중·이해함)와 이해도 1~5로 바꾸고, 사용자의 원문을 메모(`대화: …`)로 남깁니다.

## 화면 동작 (홈 채팅)

1. 처음 글을 보낼 때 한 번 동의를 받습니다. 대화 내용을 AI(OpenAI)로 보낸다는 안내이고, 파일 분류 동의와 따로 받습니다(`unilink:chat-record-consent`). 거부하면 저장하지 않고, 다음에 보낼 때 다시 묻습니다.
2. AI가 짧게 답하고, 그 아래 **저장 카드**에 저장한 내용이 바로 나옵니다.
   - ✓ 저장됨 → 연필(수정): 상태·이해도 / 진도·난이도·빠르기 / 문항 이해도를 고쳐 다시 저장합니다.
   - ↺(취소): 되돌립니다.
3. **과목·날짜가 말에 없으면 항상 되묻습니다.**
   - 과목: 이번 학기 과목 버튼을 보여 줍니다.
   - 날짜: 그 과목의 최근 수업일 3개 버튼과 날짜 선택을 보여 줍니다.
   - 같은 번호의 문제가 여러 파일에 있으면 파일 버튼을 보여 줍니다.
   - 버튼 대신 글로 답해도 됩니다. 그러면 앞 메시지와 함께 다시 해석하고, 되묻던 항목은 새 결과로 바뀝니다.
4. 수업이 없는 날(보강, 시간 미정 과목)의 진도는 그 날짜로 시간 없는 회차를 만들어 저장합니다.
5. 대화 원문은 보관하지 않습니다(새 채팅·새로고침 시 사라짐). 저장된 진도·이해도는 남습니다.
6. 데모·비로그인에서는 AI를 부를 수 없어 "로그인하면 …" 안내만 나옵니다.

## 되돌리기 규칙

- 주제 이해도: 관측 기록은 지우지 않는 구조라 **이전 상태를 새 기록으로 다시 남깁니다**. 이전 기록이 없던 주제는 `미학습`으로 돌립니다. 대화로 새로 만든 주제는 `archived`로 숨깁니다.
- 수업 회차: 이전 값으로 되돌리고, 새로 만든 회차는 지웁니다. 지운 회차는 기존 동기화가 DB에서도 삭제 표시합니다.
- 문제은행: 문항별 이전 이해도로 되돌립니다.

## 서버

- 새 Edge Function `chat-record`(`supabase/functions/chat-record`, 검증·스키마는 `_shared/chatRecord.ts`)
  - 해석만 하고 저장은 브라우저가 기존 경로로 합니다. OpenAI `store: false`, 서버 로그에 원문을 남기지 않습니다.
  - 입력: 메시지, 직전 대화 6개, 오늘 날짜, 이번 학기 과목(이름·코드·요일), 과목별 주제 목록, 문제은행 파일·문항 번호
  - 응답은 엄격한 JSON 스키마로 받고, 서버에서 다시 검사합니다. 모르는 과목·파일·문항, 범위 밖 값, 내용 없는 기록은 버립니다.
  - 모델: `CHAT_RECORD_MODEL` → 코칭 설정의 분석 모델 → `COACHING_MODEL`
- 마이그레이션 `0035_chat_record.sql`: `reserve_file_classification`에 `chat` 종류를 추가했습니다(24시간 300회). 파일 분류 한도(200회·강의계획서 50회)와 따로 셉니다.

## 가상 사용자 대화 시뮬레이션 (22개)

- 실제 AI 키가 로컬에 없고 `chat-record`도 배포 전입니다. 그래서 **모델 응답만 시나리오별로 정하고**, 나머지는 실제 코드로 돌렸습니다.
  - 실제 코드로 돈 것: 서버 입력·응답 검사, 되묻기, 저장, 수정, 되돌리기
  - 로그인 DB는 브라우저 안의 가짜 DB(주제·관측 기록)로 바꿨습니다. 시뮬레이션용 임시 코드는 확인 후 되돌렸습니다.
- 시나리오:
  - 기존 주제
  - 같은 새 주제 두 번
  - 과목 없음 → 글로 답
  - 날짜 없음 → 글로 답
  - 미래 날짜
  - 같은 번호가 여러 파일에 있음
  - 없는 문항
  - AI가 과목을 짐작함
  - 약칭(소공·영어)
  - 깨진 AI 응답
  - 한도 초과
  - 수정 후 취소
  - 새 주제 취소 후 다시 말함
  - 한 메시지에 3건
  - 개념 질문
  - 보강일
  - 지시 무시 요청
  - 응답 중 새 채팅
  - 날짜 버튼
  - 되묻는 중 다른 주제
  - "알고 있어" 오인

### 찾아서 고친 문제

| 상황 | 문제 | 수정 |
| --- | --- | --- |
| 한 메시지에 같은 새 주제가 두 번 | 주제가 2개 만들어짐(동시에 저장) | 기록을 하나씩 순서대로 저장 |
| 날짜를 물었는데 "어제"라고 글로 답함 | AI가 무엇을 묻는 중인지 몰라 저장 안 됨 | 되묻는 중인 기록을 `확인 중: …` 한 줄로 AI에게 함께 보냄 |
| "다음 주 목요일 수업 …" | 아직 안 한 수업 회차가 저장됨 | 오늘 이후 날짜는 버리고 날짜를 다시 물음 |
| 과목을 말하지 않음("교착 상태 어려워") | AI가 과목을 짐작하면 묻지 않고 저장 | 사용자가 과목 이름·코드·약칭을 말했을 때만 그 과목을 씀. "알고 있어"는 알고리즘으로 보지 않음 |
| 되묻는 중에 다른 주제를 말함 | 되묻던 기록이 사라짐 | 같은 기록에 답한 경우에만 바꿈 |
| 문제은행에 없는 번호 | AI는 "기록할게요"인데 아무것도 저장 안 됨 | "과목이나 문항 번호를 찾지 못해 기록하지 않았어요" 안내 |

- 문제없이 지나간 경우:
  - 깨진 응답·한도 초과에도 화면이 멈추지 않았습니다.
  - 지시 무시 요청이 기록을 지우지 않았습니다(모르는 종류는 버림).
  - 수정 후 취소하면 대화 전 상태로 돌아갔습니다.
  - 보강일 회차는 시간 없이 저장됐습니다.
  - 응답 중에 새 채팅을 눌러도 오류가 없었습니다.
- 남은 한계:
  - 실제 AI가 약칭·날짜 표현을 얼마나 정확히 읽는지는 배포 후 확인이 필요합니다.
  - 과목 확인 규칙 때문에 목록에 없는 별명(예: "OS")으로 말하면 과목을 다시 묻습니다.
