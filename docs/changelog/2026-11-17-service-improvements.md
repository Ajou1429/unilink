# 2026-11-17 서비스 개선 및 DB 0041 반영

## 오늘 main에 반영한 수정

1. **채팅 실행·기록**: 요청을 분석한 실행 내용을 예/아니오로 확인하는 프로토콜, 계정별 대화 저장/조회와 이전 실행 기록 표시를 통합했다. 완료 기준 표시와 승인 충돌 처리도 연결했다. 이 부분은 앞선 f67f234 릴리스이며 이번에 재배포할 서버 함수는 없다.
2. **오늘 계획·안내**: 중복 인증 요청을 줄이고 계획 조회 연결 오류 안내/재시도를 추가했다. 채팅 하단 자동 저장 안내 문구는 제거했다(d96c781).
3. **수업 자료·일정**: 강의노트 중간/기말 분리를 없애 전체 자료를 표시한다. 각 수업 과제·시험을 눌러 세부사항을 확인하고 수정한다. 수동 입력 팝업을 확대했다(711838a).
4. **완료 일정**: 과제 체크박스로 완료/취소를 저장하고 재접속 시 반영한다. 완료 과제와 지난 시험은 ‘완료 일정’에서만 펼쳐 보며 일정 카드를 줄였다. 지난 시험의 분리는 날짜 판정이며 수행 완료 상태를 자동 기록하지 않는다(711838a).
5. **클립보드 파일 첨부**: 채팅에서 Ctrl+V/⌘V로 브라우저가 제공하는 파일을 첨부한다. 기존 텍스트는 유지하고 자동 전송하지 않는다. 일반 텍스트 붙여넣기도 유지한다.
6. **상세 강의자료 우선**: 같은 수업의 거의 같은 원문을 포함하는 자료라면 본문 고유 내용이 더 많은 상세본을 대표로 표시한다. 짧은 재업로드는 상세본을 재사용한다. 파일명·용량·같은 주제만으로 합치지 않는다. 원본 노트·Drive 원본·문제/학습 기록은 삭제하지 않는다.
7. **시간표 겹침**: 수업·시험/기타 일정·반복 일정이 겹치면 좌우 열로 나눈다. 겹치지 않으면 전체 폭을 사용하고 모바일에서는 시간표 내부 가로 스크롤로 최소 폭을 확보한다. 수업 클릭 이동을 유지한다.

## 운영 DB 0041

- `note_content_profiles`와 소유자 전용 저장 RPC를 추가했다. 원본 버전·수정시각에 비교 정보를 연결하고 원본 변경 시 오래된 결과를 사용하지 않는다. 원본 충돌은 HTTP 409로 반환한다.
- 비교 정보는 해시·고정 크기 특징 등이며 PDF 본문이나 사용자 대화 원문을 저장하지 않는다. 새 서버 함수 배포 없이 DB RPC와 웹을 연결한다.
- 기존 public 테이블 36개 데이터와 함수 정의를 암호화 복구본으로 보관하고 전후 일치를 검사했다. Auth/Storage 전체 백업은 아니다.
- 임시 계정 2개로 본인 저장/조회·다른 계정 차단·익명/직접 쓰기 차단·버전/수정시각 충돌·원본 불변·삭제 전파를 운영 환경에서 확인했다. 테스트 계정은 삭제했다. 유료 AI 호출은 하지 않았다.
- **0040은 적용하지 않았다.** 별도 Drive 삭제 자료 재동기화 방지 범위/함수 계약 검토가 필요하다.

## 채팅 카드·대화 이어가기·일정 통합 후속 릴리스

- 확인 직전 요청을 큰 명사형 제목·개조식 요약·하단 시간으로 표시한다. 추가 질문과 처리 결과는 대화로 표시하며 대화 복귀 시 원래 요청/첨부명과 최근 맥락, 미확정 입력을 이어받는다. 현재 소유권·자료를 재확인한 뒤 새 승인에서 반영한다.
- 시험·과제·개인/반복 일정을 주간·월간에서 함께 표시한다. 월간 반복 항목은 원본 일정 수정으로 연결하고 주간에서는 한 번씩 표시한다. 장소/메모가 없는 기존 일정의 수정도 보완했다.
- 로그인된 실제 계정의 로컬 브라우저에서 주간/월간 과제·반복 일정과 12월 Term Project 표시를 읽기로 확인했다. 사용자 자료를 수정하는 시험은 하지 않았다. 운영 임시 계정으로 새 카드/미확정 입력 JSON 저장·재조회, 다른 계정의 조회 차단, 정상 revision 갱신·익명/직접 쓰기 거절을 확인하고 모두 삭제했다. 충돌 응답 검사는 아래 미해결 항목을 따른다. 유료 모델 호출은 없었다.
- 전체 Node 302개와 추가 삭제 선행 조건 회귀 5개, Edge 12개·Edge 타입·TypeScript·경고 0 린트·webpack 빌드 통과. PC/모바일 가상 API 검사에서 대화/기록 복귀·새 확인·중복 저장 방지와 일정 양쪽 표시/수정을 확인했다. 기능 커밋 `d223443`의 [Pages 배포](https://github.com/Ajou1429/unilink/actions/runs/44007568677)와 [보안 검사](https://github.com/Ajou1429/unilink/actions/runs/44007568573)가 모두 성공했다. 배포본 HTTP 200 및 로그인된 실제 계정의 주간/월간 과제·반복 일정과 달력 경계의 Term Project 표시를 확인했다.

### 0040 운영 검토

- 운영 이력은 0039 다음 0041이며 0040은 미적용이다. 운영 `drive-sync` v9와 `drive-webhook` v9의 소스를 API로 내려받아 확인했으며 삭제 자료 제외 코드가 포함되어 있지 않았다. 로컬 코드는 두 함수가 공유하는 `driveNotes.ts`에서 `dismissed_drive_files`를 조회한다.
- 후속 운영 반영 단위는 0040과 `drive-sync`/`drive-webhook`이다. DB만 적용하면 운영 동기화가 삭제 자료를 다시 가져올 수 있다. 이번 작업은 이 의존성을 검토했으며 해당 운영 변경을 실행하지 않았다.
- 웹의 자료 삭제 순서를 보완했다. 삭제 제외 기록을 먼저 저장하고 성공한 뒤 연결된 문제/노트 삭제를 진행한다. DB 미적용 오류가 나면 0040 필요 안내를 표시한다. DB 오류 이전에 연결된 문제를 먼저 지우던 부분을 회귀 검사로 막았다. 여러 저장소에 걸친 전체 삭제의 원자성까지 보장하는 변경은 아니다.

### 코칭 후속 검토

- 다음 기능은 실제 공부시간·해낸 범위·부분 완료·미완료 사유를 적은 조작으로 기록하고 다음 추천에서 같은 관측이 사용되는지 확인하는 5번이다. DB `study_sessions`와 기존 개인화 근거 경로를 활용한다.
- 실제 과목 2개/개인 목표 1개의 PDF·이해도·시간 조건 대조와 비용/지연 평가, 승인형 재계획(6번), 개인별 시간/분량 보정(7번)도 남아 있다. 이번에는 추가 코칭 개발이나 유료 품질 평가를 시작하지 않았다.


### 운영 충돌 응답의 남은 확인

- 새 형식 저장/조회·revision 정상 증가는 운영에서 통과했다. 다른 계정의 갱신 시도는 오류로 거절됐지만 기대한 SQLSTATE `40001` 응답을 받지 못해 최초 충돌 검사 전체를 통과로 기록하지 않는다. 두 번의 독립 검사에서 만든 임시 계정 총 4개는 삭제 확인했다.
- 현재 운영 `save_chat_conversation`의 SQLSTATE 40001 경로와 PostgREST 재시도/HTTP 응답을 확인하고, 기존 0038의 HTTP 409 변환 방식을 이 함수에도 적용할지 검토해야 한다. 이번 릴리스는 해당 운영 RPC를 변경하지 않았다. 앞선 진행 안내에서 운영 충돌 검증까지 완료로 말한 부분은 이 결과로 정정한다.
- 후속 순서는 대화 저장 충돌 HTTP 응답 확인, DB 0040과 Drive 함수 2개 운영 반영, 코칭 실제 수행 기록(5번) 순으로 정리한다. 사용자 본인 자료에 대한 쓰기 시험과 유료 모델 품질 대조는 별도 확인이 남아 있다.


## 자동 분석 및 운영 후속 최종 반영

- 대화에 필요한 PDF 분석을 자동 진행하고 분석 결과로 원래 요청을 이어 처리한다. 같은 버전의 분석을 재사용하고, 분류만/파일명만/분석 거절을 우선한다. 본문 분석 범위를 포함한 대화 동의 v3를 한 번 갱신하며 등록/저장은 확인 카드에서 승인한다.
- 운영 DB 0040 적용과 drive-sync v10 / drive-webhook v10 배포를 완료했다. 삭제한 Drive 파일을 다시 가져오지 않는 공유 코드가 실제 배포본에 포함된 것을 확인했다.
- 새 0042를 운영에 적용해 save_chat_conversation의 충돌을 HTTP 409 + 오류 코드 40001로 반환한다. 정상 revision 갱신과 충돌 거절, 계정 격리·익명/직접 쓰기 차단을 실제 API로 확인했다. 이전 충돌 응답 미통과 항목을 이번 결과로 해소했다.
- chat-record v8을 배포했고 공유 분석 지침이 로컬과 일치하는 것을 배포 소스로 확인했다. 기능 main/웹 CI 결과는 확인 후 기록한다.
- 기존 public 테이블 37개/함수의 암호화 복구 사본과 함수별 이전 배포 소스를 보관했다. 임시 계정으로 삭제 제외 기록 RLS, 실제 공유 helper의 재유입 차단/타 계정 정상 등록·재시도 단일 버전을 확인하고 검사 계정을 모두 삭제했다. 실제 Google 파일 동기화나 유료 OpenAI 분석 호출을 새로 실행한 검증은 아니다.
- 전체 Node 307개와 Edge 12개, 타입·경고 0 린트·정적 빌드, PC/모바일 모의 API 자동 분석/등록 전 확인·분석 재사용 검사를 통과했다. 복구가 필요하면 웹과 해당 함수의 이전 소스를 사용하며 새로운 사용자 기록을 백업으로 덮어쓰지 않는다.
- 다음은 실제 사용자 PDF의 분석·등록/계획 내용 확인과 코칭 수행 기록(5번)이다. 6~7번 및 자료/수준 대조 평가도 후속으로 남긴다.
