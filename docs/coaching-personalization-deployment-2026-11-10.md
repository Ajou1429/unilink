## 운영 환경 검증

개인정보 없는 임시 계정 2개와 합성 목표·주제·제안을 생성했다. 아래 실제 인증 API/RPC 검증을 마친 후 두 계정과 소유 데이터를 삭제했고 잔여 계정 0건 및 기존 자료 지문을 재확인했다.

1. 운영 DB 트리거가 시험 요청 원문을 제거하고 요청 해시/일회성 플래그를 보존.
2. 실제 `coaching-propose` 인증 요청으로 저장 제안 재생 성공. 같은 요청 키에 다른 문장이 오면 409로 거절.
3. 만족도 저장·수정·반복 저장 시 단일 관측 유지, 허용 점수 밖 입력 거절.
4. 다른 사용자의 평가/근거 조회 차단 및 수정 거절. 타인의 삭제 요청은 원래 평가를 지우지 않음.
5. 자기 이해도 2건이 최신 1건/과거 1건으로 중복 없이 다음 입력에 포함. 만족도와 일회성 요청 존재 여부도 전달되지만 이전 원문은 없음.
6. 만족도 삭제 후 이후 모델 입력에서 해당 평가 제외.
7. 최소화된 요청 payload에서도 기존 계획 승인 성공. 반복 승인 시 같은 계획을 반환하며 항목 중복 없음.

위 제안은 검증용으로 저장한 합성 제안이지 LLM이 새로 생성한 결과가 아니다. 새 유료 LLM 생성·PDF 분석·검색 호출은 0회였고, 저장된 제안 재생은 생성 작업을 예약하지 않았음을 확인했다. 실제 운영 DB 조회로 다음 모델 입력을 구성했지만, 새로운 전체 생성의 응답 품질이나 교육 효과까지 검증한 것은 아니다.

추가로 Node 132개 자동 테스트 및 전체 Edge 코드 타입 검사도 통과했다. 앞서 수행한 Edge 10개·빌드·린트·PC/모바일 가상 API 시험은 이전 릴리스 기록을 따른다.

## 사용 시점과 다음 작업

이제 사이트에서 계획 제안을 받은 뒤 만족도·난이도·시간 적합성을 저장하고, 선택 목표의 '내 개인화 근거 기록'을 확인할 수 있다. 이전 요청 원문은 새 요청으로 재사용하지 않는다. 없는 기록은 만들어 채우지 않고 추천은 잠정 판단으로 진행한다.

운영 조회 시 실제 학습 실행·주제 이해도 관측·만족도·문제은행 연결은 아직 0건이었다. 기능 배포만으로 개인화 데이터가 이미 축적되었다거나 가중치 학습이 끝났다고 주장하지 않는다.

- 남은 확인: 사용자 본인의 새 계획 1회 사용과 평가 저장/삭제 경험 확인, 실제 PDF·추천 내용 정확도 대조. 새 LLM 호출은 실제 사용 시 발생한다.
- 다음 기능 개발: 기존 4번 작업 범위·완료 기준·출처 구조화.
- 이후: 5번 항목별 실제 수행 기록 UI → 6번 승인형 재계획 → 7번 비교 가능한 본인 기록 기반 시간·분량 보정.
- 병행: 입력 근거와 비용·지연 대조, 복구본 보관 종료 검토. 파인튜닝은 이번 방향이 아니다.
