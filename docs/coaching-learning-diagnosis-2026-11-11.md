# 학습 수준 진단과 능동적 시험 대비 코칭 요구사항

정리일: 2026-11-11. 아래 현행 차이 표는 구현 전 입력 v5/지침 v16과의 대조 기록이다. 이후 실제 코드 구현 범위·입력 v6/지침 v17·DB 0032·RAG 발전 계획은 [이번 구현 기록](coaching-diagnosis-release-2026-11-11.md)을 우선한다. 운영 DB·서버 배포와 실제 품질 검토는 별도다. 기준 하네스는 [통합 구조](database/coaching-harness.md), 실행 순서는 [우선 작업 원장](coaching-priorities.md)을 따른다.

## 1. 해결할 문제의 정의

코칭의 핵심은 과목 우선순위를 숫자로 정하고 시간을 배분하는 것이 아니다. 먼저 **무엇을 어느 깊이까지 배워야 하는지**, **사용자가 그 내용을 이해할 선수 기반과 경험을 갖췄는지**, **현재 수업과 본인 학습이 어디까지 진행됐는지**를 확인한다. 그 차이와 시험·과제 일정으로 구체적인 활동·분량·복습·확인 시점을 제안한다. 여러 활동이 시간 안에 들어가지 않을 때의 일정상 선택은 필요하지만 수준 진단을 고정 우선순위 공식으로 대체하지 않는다.

- 내용·요구 깊이: 강의계획서/노트 PDF의 개념·예제·과제·평가 범위, 실제 문제은행 내용, 출처가 있는 검색 자료를 활용한다. 자료 간 충돌과 버전을 표시하며 일반 검색이 실제 강의 범위를 덮어쓰지 않는다.
- 개인 기반: 본인의 관련 선수 개념·과거 학습/확인 결과·문제은행 단계·현재 이해도와 기록 시점을 확인한다. 유사 과목 이력이 있다는 것만으로 숙달을 확정하지 않는다.
- 수업 진행: 회차별 진도·수업 속도·체감 난이도·본인 이해도는 구분한다. 진도가 빠르다는 평가가 곧 본인 이해도가 낮다는 뜻은 아니다.
- 시험 대비: 과제와 강의 예제는 시험 대비 역량을 만드는 과정으로도 연결한다. 그러나 실제 평가와 연결 근거가 없으면 시험 범위라고 단정하지 않고 과제 고유의 제출 기준·마감도 유지한다.
- 현재 요청: 사용자의 텍스트는 원하는 범위·상황·어려움·방법을 이해하는 중요한 입력이다. 사용자가 놓친 시험·과제·복습 필요까지 지워 버리는 절대 명령이나 지속 선호로 다루지 않는다.
- 반복 확인: 중요·고난도 내용을 판별하고 최근 수행·확인 결과·남은 기간을 보고 재확인/회독/기출 적용을 제안한다. 매번 전체 PDF 재분석이나 같은 확인 문제 반복을 뜻하지 않는다.

## 2. '수준'을 하나의 점수로 만들지 않는다

| 판단 대상 | 확인할 근거 | 오해하면 안 되는 점 |
| --- | --- | --- |
| 과목/시험이 요구하는 깊이 | 실제 PDF의 목표·선수지식·예제/과제·평가, 문제 내용, 검색 출처 | 검색의 일반 난이도를 해당 강의의 확정 범위로 취급하지 않음 |
| 분야에 대한 친숙함·기본 베이스 | 본인 관련 개념 학습 이력, 날짜 있는 관측·채점·수행 사례 | 수강/완료/회독 횟수만으로 실력 확정 금지 |
| 현재 배운 범위 | 회차·자료 페이지/단원·사용자 진도 기록 | 업로드/분석 범위·계획서 주차와 실제 수업 진행을 구분 |
| 현재 이해와 적용 능력 | 자기평가·문제은행 학습 단계·확인 문제/실제 수행을 각각 사용 | 서로 다른 척도를 평균하거나 자기평가를 객관 점수로 바꾸지 않음 |
| 학습 부담과 속도 | 같은 종류·수준·범위 활동의 계획 대비 실제 수행, 중단 여부 | 기록이 없으면 잠정 추정. 웹 후기의 소요시간을 개인 실측으로 사용하지 않음 |

검색은 개념·선수 관계·일반적인 요구 수준을 보완하는 도구다. **특정 사용자가 지금 알고 있는지는 검색이 아니라 개인 관측으로 판단**한다. 출처가 부족한 평균 학습시간이나 '사람들이 보통 이 정도 한다'는 수치는 사실로 만들지 않는다.

## 3. 근거가 있거나 없을 때의 경로

1. 연결된 PDF/계획서가 있으면 저장된 분석·출처·파일 버전을 우선 재사용한다. 필요한 구간이 없거나 파일이 바뀔 때만 동의·예산 범위에서 추가 분석한다.
2. 문제은행이 있으면 연결된 학습 단계뿐 아니라 필요한 문항의 개념·요구 역량·자료 근거도 읽을 수 있어야 한다. 문항 번호만으로 난이도나 내용 추정 금지. 원문 전송은 별도 자료 이용 경계 안에서 수행한다.
3. 실제 자료가 부족하면 과목/자격증의 식별 정보·주제·목표 수준으로 제한된 검색을 한다. 출처·조회 시점·가정한 판본/범위를 반환한다. 동명이거나 범위가 불명확하면 일반적인 잠정 수준임을 밝힌다.
4. 검색 결과와 본인 이력의 의미를 코칭 단계에서 결합한다. 외부 검색 질의에 사용자 계정·성적·자유 요청 원문·개인 학습 이력을 그대로 보내지 않는다. 관련 개념만 최소화하며 기존 동의 범위를 유지한다.
5. 자료/검색이 없거나 동의하지 않아도 입력한 정보와 일반 지식으로 구체적인 잠정 활동을 제안한다. 검색 실패를 성공으로 표시하지 않는다. 소유권 오류나 필수 실행 사실 누락은 조용히 우회하지 않는다.

검색을 계획 생성 때마다 무조건 수행하지 않는다. 과목/시험 범위·판본/연도·자료 버전·검색 시점이 맞는 결과는 재사용한다. 개인 이해도만 바뀌면 개인 판단을 갱신하고 같은 공개 개념 검색을 중복 호출하지 않는다.

## 4. 텍스트를 존중하면서 판단도 돕는 계약

현행 지침의 '현재 요청 우선'은 **과거의 소프트 선호보다 우선**이라는 의미로 한정해야 한다. 확인된 시간·학습 제외·승인 경계는 지키되 현재 문장 하나 때문에 다가온 시험/과제와 필요한 재확인을 무시하지 않는다.

| 요청 종류 | 기대 동작 |
| --- | --- |
| '이번 주 A 위주로' | A를 중심으로 하되 허용된 검토 범위에서 B의 임박한 시험/중요 재확인 필요를 확인. 근거와 A의 배정에 미치는 영향을 보여주고 선택 가능한 대안을 제안 |
| 'A만, B는 넣지 마' | B를 몰래 일정에 추가하지 않음. 중요한 일정이 있으면 위험과 별도 대안을 짧게 알리고 변경은 사용자 선택으로 남김 |
| '오늘 30분만 가능' | 제한을 넘기지 않음. 더 필요한 활동은 별도 제안/이월로 표시하며 시간을 늘려 저장하지 않음 |
| '시험은 없어'인데 DB에 시험 일정이 있음 | 충돌을 표시하고 일정 확인을 권함. 텍스트나 오래된 DB 어느 하나를 무조건 확정 사실로 삼지 않음 |
| 'JOIN 결과가 왜 달라지는지 모르겠어' | 단순 학습 선호가 아니라 이번 활동의 내용/어려움으로 해석하고 관련 단원·예제를 선별. 영구적인 취약 주제로 자동 저장하지 않음 |
| 빈 텍스트 | 자료·상태·일정·허용된 후보를 바탕으로 코칭. 추가 입력을 기다리도록 바꾸지 않음 |

텍스트에서 이번 범위·의도·어려움·방법·제외 등을 일시적으로 구분하는 것은 가능하지만, **파싱한 문장 요약을 새 장기 프로필에 저장하는 우회 경로는 만들지 않는다.** 계획 결과에 내용이 반영될 수 있다는 기존 보존 안내는 유지한다. 목표 ID/시험 날짜/새 역량 상태를 텍스트만으로 DB 사실에 자동 확정하지 않는다.

## 5. 요청 기간과 추천 범위를 구분

| 모드 | 추천 대상과 방법 | 승인 경계 |
| --- | --- | --- |
| 하루 계획 | 사용자가 고른 오늘의 작업/목표 중심. 중요한 다른 일정은 우선 별도 알림·검토 후보로 제공 | 선택 범위를 몰래 확장하거나 하루 예산 침범 금지 |
| 주간 계획 | 선택 목표의 시험/과제·진도·선수 공백·복습 필요를 함께 검토. 다른 목표도 보려면 사용자에게 드러난 주간 검토 범위가 필요 | 미선택 목표는 별도 후보로 제안하고 선택/범위 확정 뒤 실행 계획에 편입 |
| 시험 준비/자격증 | 시험 범위·현재 준비 수준·이전 회독/기출·남은 기간으로 단계와 확인 기회를 제안. 실제 시험 이후에 대비 활동을 배치하지 않음 | 제공되지 않은 기출/실제 시험지를 본 것처럼 만들지 않으며 생성 문제는 따로 표시 |
| 3주 시험 준비 | 21일의 준비 목표/단계 전망과 짧은 실행 구간을 분리하고 실행 결과로 다음 구간을 갱신 | 현재 API가 1~14일만 지원함을 명시. 기존 14일 요청을 21일로 바꾸거나 여러 제안을 단순 합쳐 구현 완료로 간주하지 않음 |

다른 과목 후보 조회를 추가할 때도 본인 소유·활성 목표·필요한 기간/필드·최대 건수로 한정한다. 기존 계획 생성의 `goal_ids` 제한은 유지한다. 후보 확인과 실제 일정 작성은 서로 다른 단계이며, 새로운 후보에 대한 PDF/검색 동의나 추가 비용을 자동 확장하지 않는다.

## 6. 복습/재확인 판단

후속 판단은 '중요하고 어려우면 매번 시험'이 아니라 다음 근거를 함께 본다.

- 실제 평가 범위나 후속 개념에서의 중요성, 해당 수업의 요구 깊이.
- 마지막 학습·회독·독립 풀이·이해 확인의 날짜와 범위.
- 최근 이해도/채점의 불확실성·오래됨·상충, 새 자료/내용의 변화.
- 선수 개념과 현재 적용 과업의 관계, 남은 시험 기간·가용시간·기존 계획 중복.
- 사용자가 실제로 수행한 회독·기출 범위. 기록이 없으면 '다시 한 회독'을 이미 한 사실처럼 추천하지 않음.

결과는 복습할 개념·자료/페이지·활동·완료 기준·이 시점에 권하는 이유로 제안한다. 짧은 설명/적용/다른 예제의 확인 등 범위에 맞는 활동을 선택한다. 확인 문제 결과가 좋으면 같은 검사를 기계적으로 반복하지 않고 다른 적용이나 복습 유예도 판단할 수 있어야 한다. 활동 완료만으로 학습 효과나 숙달을 확정하지 않는다.

항상 동일한 회독 수·간격·시간 비율을 강제하는 규칙은 두지 않는다. 무제한 검색/퀴즈 루프로 불확실성을 해소하려 하지 않고 호출/시간/사용자 부담을 제한한다. 이해도 확인은 계획에 포함할 수 있는 활동이지 선택 입력을 채울 때까지 코칭을 멈추는 필수 질문 절차가 아니다.

## 7. 현행 코드와의 차이

아래는 로컬 소스 `15d3e1c` 계열 확인 결과다. 실제 운영 데이터가 충분히 쌓였다는 의미는 아니다.

| 요구 | 현재 경로 | 남은 보완 |
| --- | --- | --- |
| 내용·수준·선수지식 | `courseKnowledge.ts`의 단원 concepts/prerequisites/required_depth 및 검색 결과, 모델 지침 | 수준 근거가 활동 선택에 쓰였는지 검증, 개인 선수 경험과 요구 수준의 명시적 대조 |
| 수업 진도·속도·체감 | `context.ts`의 최근 회차, pace·메모·legacy 난이도/속도, 자기 이해도/채점 별도 투영 | 원본/시점/척도를 유지한 적용 평가, 학생 체감만으로 객관 난이도 결정 금지 |
| 문제은행 내용 활용 | `problemBank.ts`가 연결 문제 라벨·0~5 단계·시점을 전달 | 현재 코칭에 문항 본문/필요 역량은 전달하지 않음. 별도 문항 자료 분석/근거 연결 필요 |
| 자료 없는 검색 | `courseKnowledge.ts`는 추출 단원/개념/깊이로 검색 작업 구성. 단원이 없으면 unavailable | 과목/자격증 식별·공식 범위 기반의 제한된 대체 경로 설계. 검색 여부/성공을 정직하게 전달 |
| 자유 요청과 자료 선별 | UI는 텍스트를 constraints로 전송. `context.ts` 선별 focus는 desired_outcome·시험 범위·마감·토픽 중심 | 텍스트의 이번 내용/어려움을 자료 선택과 코칭에 일관되게 반영할 일시적 해석 경로. 명령/자료 경계·비저장 유지 |
| 개인 선수 경험 | `context.ts`는 선택 목표별 이력 중심 | 관련 선수 근거만 본인 DB에서 제한 조회. 이름 유사성만으로 자동 숙달/과목 매핑 금지 |
| 요청 밖 시험/복습 | `daily_plan`은 daily_sources 한정. 코칭 근거는 선택 goal_ids 중심 | 주간/시험의 검토 범위 및 추가 후보 안내 계약·화면. 현재는 미선택 과목 진단 경로 없음 |
| 능동 복습/회독 | 현재 이해도/기록/마감 입력과 topic_review 지침 존재 | 마지막 확인 범위/시점·회독·기출 수행의 연결 및 중복 방지. 고정 시간표 템플릿 대체 |
| 3주 준비 | `contract.ts` 1~14일, UI 시험 대비 14일 | 준비 horizon과 실행 window 분리, 다음 구간 재계획/승인. 현재 미지원 |

## 8. 하네스/DB에 연결할 구현 단위

새 데이터나 경로 이름은 제안이며 이번에 생성하지 않았다.

1. **R1 진단 계약:** 기존 goal brief에 과목 요구 수준·개인 선수 기반·현재 배운 범위·이해 확인 상태의 근거를 구분한다. 수준·친숙함의 출처/관측 ID·시점·불확실성·미확인 영역을 명시하고 근거 없는 종합 점수는 만들지 않는다. 근거 선택은 기존 DB/분석 캐시를 재사용한다.
2. **R2 요청/후보 계약:** 일회성 텍스트 해석과 계획 모드별 범위·명시 제외·소프트 요구를 구분한다. 미선택 과목을 검사하려면 별도 검토 범위와 후보 결과를 설계한다. 기존 실행 goal_ids/시간 제한 및 최종 승인 경계를 우회하지 않는다.
3. **4번 완료 기준:** 진단된 공백/시험 역량 → 구체 과업·자료 범위·완료 기준·근거 참조를 출력/검증/저장/화면에서 보존한다. 검색 추천을 실제 강의 범위로 변환해 저장하지 않는다.
4. **5번 실제 결과:** 기존 study_sessions·topic_observations·topic_check_states·문제은행을 중심으로 활동 종류·해낸 범위·마지막 확인·회독/기출 수행을 연결한다. 자유 채팅을 이해도 사실로 자동 승격하지 않는다.
5. **6번 재계획:** 새 관측·마감·남은 범위로 복습/회독/기출 활동과 다음 구간을 조정한다. 21일 준비의 전망은 별도 계약이 갖춰진 뒤 지원한다.
6. **7번 개인 보정:** 비교 가능한 관측이 쌓이면 본인 시간/분량 추정을 조정한다. 코칭 대상의 일반 난이도와 개인 부족분은 분리하고 파인튜닝·보편 고정 가중치로 바꾸지 않는다.

모든 판단마다 새 LLM을 여러 번 호출하는 설계는 피한다. 기존 분석/검색/관측으로 구성한 구조화 근거를 최종 코칭이 함께 해석할 수 있게 먼저 개선한다. 별도 진단 호출이 필요한지는 품질·토큰·지연 비교로 결정한다. H0-A의 안전 승인·H0-B/C의 관측·평가를 함께 적용한다.

## 9. 반영 확인용 평가 사례

| 사례 | 통과 기준 |
| --- | --- |
| 같은 과목, 선수 기반만 다름 | 관련 경험이 없는 경우의 보완과 충분한 근거가 있는 경우의 적용 활동이 달라짐. 근거/가정 설명 |
| 같은 속도 평가, 이해도는 다름 | 수업 속도와 본인 숙달을 동일시하지 않고 활동 부담·범위가 달라짐 |
| 은행 단계만 있고 본문 없음 | 문항 내용/난이도를 읽었다고 주장하지 않음 |
| PDF/은행 없음 | 동의·한도 안의 검색 또는 일반 지식 잠정안. 검색 unavailable을 성공으로 표시하지 않음 |
| 텍스트에 구체적 어려움 있음 | 해당 내용이 자료 선별·활동에 반영되고 다음 빈 요청에는 지시로 재사용되지 않음 |
| 'A 위주' + B 시험 임박 | 주간 검토 범위 내에서는 B의 준비 필요를 놓치지 않음. 미선택 B의 일정 추가는 사용자 선택 뒤 수행 |
| 'A만/B제외' + B 시험 임박 | 위험·대안은 알리되 제외를 무시해 저장하지 않음 |
| 오늘 작업 요청 | 다른 과목을 몰래 추가하지 않고 선택 작업 중심. 별도 안내가 시간 예산에 섞이지 않음 |
| 어려운 주제, 최근 확인 부재/상충 | 필요한 범위의 짧은 재확인을 추천하고 근거를 제시. 과도한 반복 금지 |
| 같은 주제, 최근 독립 수행 근거 충분 | 무조건 같은 문제/기초를 반복하지 않고 필요한 적용/다른 범위 판단 |
| 자격증 시험 접근 | 기록된 범위와 기존 회독/기출 수행을 보고 필요한 재확인 제안. 존재하지 않는 기출 내용·수행 횟수 창작 금지 |
| 과제/예제와 평가 연결 | 근거가 있는 시험 역량과 연결하면서 별도 제출 기준·마감 유지 |
| 21일 요청 | 현 14일 제한을 숨기지 않고 전망/실행 구간 분리 필요를 표시. API 기간을 조용히 잘라 성공 처리하지 않음 |
| 관측/자료 삭제·버전 변경 | 과거 수준 판단/복습 후보 캐시를 무효화하고 잘못된 영구 기억 재사용 방지 |

우선 합성 입력/무료 회귀로 전달·소유권·범위·비저장을 확인한다. 실제 LLM의 적합성 비교는 같은 모델과 고정 근거에서 반복하며 별도 승인한 유료 평가 범위 안에서 진행한다. 문서 반영만으로 추천이 이미 개선되었다고 보고하지 않는다.
