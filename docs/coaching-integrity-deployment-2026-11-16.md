## 통합 검증에서 발견한 충돌 응답 보완(0038)

오래된 승인/문항/미루기 요청은 DB에서 `40001`로 올바르게 거절했지만, 실제 HTTP에서는 여러 번 응답 시간 초과가 재현됐다. DB 장시간 실행/잠금 대기는 관측되지 않았다. 1차 검증 스크립트의 완료 시각이 생성 시각보다 앞서는 합성 fixture 오류는 테스트 입력만 수정했다. 해당 오류를 서비스 장애로 집계하지 않는다.

[PostgREST 공식 오류 규약](https://docs.postgrest.org/en/stable/references/errors.html)에 따르면 `40*`는 HTTP 500이며, `PGRST` 예외로 HTTP 상태와 응답 JSON을 명시할 수 있다. 응답 지연의 인프라 내부 원인을 확정한 것은 아니지만, 사용자 상태 충돌을 HTTP 409로 전달해야 하므로 0038을 추가했다. 세 RPC의 권한·정합성 검사·변경 내용을 유지하고 직렬화 예외의 HTTP 전달만 바꾼다. HTTP 문맥에서는 409와 기존 JSON 코드 `40001`을 반환하고, 직접 SQL 호출은 기존 SQLSTATE를 유지한다. 함수 정의 교체이므로 추가 Edge 재배포는 필요하지 않다.

0038 적용 후 승인·문항 수정·미루기의 오래된 요청 3개 모두 실제 HTTP 409/JSON `40001`을 즉시 반환했다. 테스트 계정 삭제 및 기존 행 보존을 다시 확인했다. 새 회귀 테스트는 HTTP 메타데이터와 직접 SQL 호환성, 문항 변경 롤백을 검사한다. 0038·테스트·이 문서의 커밋/푸시는 아직 하지 않았다.
