# 학습 진단 하네스 구현과 RAG 발전 계획

기준일 2026-11-11. `489a446`의 Terra 설정을 유지한 코드 변경이다. 이번 작업은 Git 반영과 Word 갱신이며 **운영 DB 0032와 Edge 함수는 배포하지 않았다.** 아래 기능의 운영 사용에는 DB와 서버 적용이 선행되어야 한다.

## 2. 실제 입력과 출력

`coaching-evidence-v6`는 request, goal_briefs, shared_context를 전달한다. 요구 깊이와 개인 이해도를 합산한 단일 점수는 만들지 않는다. 현재 텍스트는 이번 요청의 내용·어려움·희망을 이해하는 데 사용하지만 명시 제외·가용시간·승인을 우회하지 않는다. 텍스트가 비어도 자료와 상태로 구체적인 잠정 과업을 제안한다.

기존 schema_version 2 응답을 유지하면서 items에 `completion_criteria {task_scope, observable_check, evidence_ids}`를 추가했다. 선택 범위 밖 조언은 `advisories`, 실행 구간 이후 전망은 `preparation_outlook`으로 분리한다. 참조 ID는 전달한 목표별 근거만 허용하고 임의 ID를 거절한다. 한 과업의 완료 기준이 여러 일정 항목에 복제되지 않도록 자동 분할은 거절하고 작은 과업으로 재생성하게 한다.

어렵고 중요한 내용은 최근 확인의 시점·부족·상충과 시험까지 기간으로 복습·새 적용·재확인 필요를 판단하도록 지침을 보완했다. 고정 회독 수나 모든 과목에 개념·문제·모의고사를 배치하는 규칙은 추가하지 않았다. 실제 기출과 LLM 생성 연습을 구분한다.

## 3. 하네스 구조

인증과 요청 범위 확인 → 본인 DB와 지식 근거 조회 → 요구 수준과 개인 기반 비교 → LLM 제안 → 근거 ID와 일정의 결정적 검증 → 제한된 수정 재시도 → 미리보기 → 사용자 승인 → 최신 상태 확인과 원자적 저장 순서다.

LLM은 학습 내용·활동·분량·잠정 시간·설명을 판단한다. 하네스는 소유권·자료 이용 동의·조회량·호출 예산·기한·시간창·중복 방지·승인·버전 기록을 맡는다. 임의 SQL이나 범용 DB 쓰기를 모델에 제공하지 않는다. 기존 단일 오케스트레이터를 확장하며 다중 에이전트나 새로운 SDK를 필수로 추가하지 않는다.

`0032_coaching_execution_contract.sql`은 `coaching_state_revisions`와 변경 트리거를 추가하고 기존 승인 RPC를 보호한다. 일정·수업·목표·주제·노트·관측·채점·학습 실행·지식 작업·문제은행·설정의 변경이 제안 이후 발생하면 새 생성이 필요하다. 동일한 내용의 재저장은 변경으로 세지 않는다. 이미 승인한 제안은 재전송해도 같은 계획 ID를 반환하고, 만료되거나 실행 계약이 없는 이전 미승인 제안은 재생성한다.

이 보호는 생성에 사용한 상태가 바뀌지 않았다는 보수적인 낙관적 검증이다. 전체 수동 일정 CRUD를 충돌 없는 스케줄러로 바꾸는 기능은 아니다. 수동 변경이 승인보다 먼저 확정되면 오래된 승인을 막지만, 승인 이후 사용자가 직접 겹치는 일정을 만드는 것까지 금지하지 않는다. 여러 실제 DB 연결의 경합·교착 재시도·운영 성능 시험은 남아 있다.

## 4. RAG의 현재 범위

현재는 PDF 전체 구조·상세 분석을 `course_knowledge_tasks`에 저장하고 현재 진도·시험 범위·주제·이번 텍스트와 관련된 구조화 단원만 선별해 최종 코칭에 넣는다. 파일 버전·해시·분석 세대·모델과 범위가 같은 결과는 재사용한다. 이는 저장 근거를 검색해 생성에 쓰는 구조이며, 전체 PDF 원문을 페이지별로 저장하고 임베딩으로 의미 검색하는 완성형 벡터 RAG는 아니다.

자료 없는 공개 검색은 월 단위로 재사용한다. 목표명·종류와 월만 캐시 키에 추가하고 기존 PDF 검색 캐시를 일괄 무효화하지 않는다. 개인 이해도나 요청 문장은 공개 검색 질의에 넣지 않는다. 같은 달 새 공식 시험 범위가 공개되었을 때의 수동 갱신 정책과 과목 동명이인·판본 식별은 후속 보강 대상이다.

문제은행은 연결된 문제의 라벨·학습 단계·시점만 현재 코칭에 전달한다. 문항 원문이 기존 DB에 보존되지 않은 경우 내용과 난이도를 소급해서 읽을 수 없다. **문항 본문 분석과 역량 연결은 아직 미구현**이며, 라벨을 본문처럼 해석하지 않도록 제한했다.

## 5. RAG 발전 순서

1. 대표 강의자료에서 현재 추출 단원이 원문·페이지·수업 수준과 맞는지 사람이 대조한다. 자기평가와 채점의 의미가 유지되는지 함께 본다.
2. 일반 텍스트 페이지는 텍스트를 우선 추출하고 수식·표·손글씨·그림만 선택적으로 이미지 분석한다. 원본 페이지 연결을 보존하고 OCR 오류를 표시한다.
3. 사용자·목표·노트·해시·버전·페이지·단원·접근권한을 가진 원문 조각을 저장한다. 구조화 요약과 원문 근거를 함께 유지하며 비공개 원문을 공개 검색에 보내지 않는다.
4. 필요할 때만 임베딩을 생성하고 어휘 검색과 의미 검색을 결합한다. 조회 전후 소유권과 버전을 검사하고, 실제 과목의 동일 개념을 우선한다. 상위 조각 수와 토큰 예산을 제한한다.
5. 근거가 부족할 때만 원문 구간을 보충하고, 노트가 수정·삭제되면 해당 조각·벡터·파생 결과를 무효화한다. 다른 과목 제목의 유사성만으로 자료를 합치지 않는다.
6. 검색 적중률과 근거 의미 일치, 답변 품질, 토큰·지연·비용을 현재 방식과 대조한다. 벡터 DB 도입 자체를 성능 개선으로 간주하지 않는다.

## 6. 지속 개선과 개인화

자료 요구 수준과 활동의 완료 기준을 먼저 안정화한 뒤, 계획 항목 ID에 실제시간·완료 범위·부분 완료·미완료 사유·이해 확인 결과를 연결한다. 만족도는 계획 선호의 관측이며 학습 성공이나 특정 주제 숙달과 구분한다. 자유 채팅 한 번이나 수락 한 번을 영구 사용자 특성으로 저장하지 않는다.

충분히 유사한 과업의 기록이 쌓이면 시간 추정 오차와 과부하·반복 이월을 분석하고 개인 DB를 통해 보정한다. 처음에는 과거 데이터에서 후보 보정을 비교하고 미래 결과가 입력에 섞이지 않도록 분리한다. 변경 전후 버전과 평가 사례를 남기고 악화되면 기능 플래그·모델/프롬프트 버전을 되돌린다. 파인튜닝이나 사용자 전체 데이터 학습은 이번 범위가 아니다.

현재 run/job의 버전·오류·사용량은 재사용하지만 모든 단계의 상세 추적과 운영 평가 대시보드가 완성된 것은 아니다. 새로운 추적에 원문 프롬프트·PDF·자유 요청을 무분별하게 저장하지 않는다.

## 7. 검증과 배포 경계

무료 합성 DB/모델 응답 테스트로 후보 소유권, 범위 밖 일정 금지, 자료 없는 검색 캐시, 완료 참조, 만료·오래된 승인·형제 제안 무효화·멱등 승인을 확인했다. Node 138개·Edge 10개·서버 타입 검사·린트·정적 웹 빌드가 통과했다. 1365px/390px 브라우저에서 선택 옵션, 완료 기준, 추가 조언, 21일/14일 분리 및 기존 일회성 요청·평가·근거 조회의 회귀를 검증했다. 실제 PostgreSQL 다중 연결 경합과 새 유료 모델 품질 비교는 수행하지 않았다.

배포 순서는 운영 DB 백업과 점검 → 0032 → `coaching-propose`와 `course-knowledge` → 웹·서버 버전 확인 → 임시 계정 권한/승인 시험 → 실제 사용자 새 생성의 품질 검토다. DB보다 새 서버가 먼저 배포되면 생성은 비용 호출 전에 503으로 중단한다. 새 UI가 이전 서버에 연결되면 추가 검토·21일 전망이 적용되지 않았다는 안내를 표시한다. 이전 미승인 제안은 재생성하며 기존 승인 계획과 학습 데이터는 삭제하지 않는다.
