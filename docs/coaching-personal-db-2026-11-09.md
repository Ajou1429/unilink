# 개인 DB 기반 코칭 개인화 반영 - 2026-11-09

## 방향

LLM 자체 파인튜닝이나 사용자 전체 데이터 학습이 아니라, 로그인한 본인의 DB 관측 기록을 매 추천의 근거로 사용한다. 선택적 입력이 있으면 반영하되, 없다고 추가 응답을 기다리거나 '공부하기' 같은 포괄 문장만 반환하지 않도록 한다.

입력 버전은 `coaching-evidence-v3`, 지침 버전은 `personal-db-v14`다. 기존 제안 API/승인/일정 validator 계약은 유지한다. 실제 모델 비교 후 커밋·푸시 대상으로 판단했으며 운영 서버 배포는 별도다.

## 1. 실제 연결한 DB

| 기존 DB | 추천에 전달하는 정보 | 제한 |
| --- | --- | --- |
| user_preferences | 선호 세션 길이, 코칭 스타일 | 강제 규칙이 아닌 힌트. 현재 사용자 요청이 우선 |
| study_sessions | 세션 ID, plan_item_id, 방법, 입력 출처, 기록 시점, 실제 시간, 부분/완료 상태, 이해도 관측 | 목표별 최근 20개, 최대 5개 목표. 실제 값이 없는 기록을 만들어내지 않음 |
| coaching_runs + coaching_feedback | 본인 실행에 연결된 수락/수정/거절 및 이유 | 본인의 최근 30개 run 중 선택 목표와 관련된 run, 최신 피드백 20개. 계획 전체 평가를 특정 주제 오답으로 취급하지 않음 |
| course_sessions / topic_learning_states / topic_check_states | 실제 수업 진도, 자기평가, 채점 결과 | 기존 구분과 자료 버전 유지 |
| course_knowledge_tasks | 분석된 단원·개념·선수지식·수준과 검색 근거 | 현재 진도와 목표 범위 관련 근거를 선별. 원문 PDF를 다시 보내지 않음 |

새 프로파일 테이블을 중복 생성하지 않는다. 현재 DB 테이블에 있는 관측을 읽어서 과목별 묶음과 공통 개인화 문맥으로 투영한다. 임의로 추론한 '이 사용자는 항상 느리다' 같은 정보를 DB 사실로 저장하지 않는다. 각 관측은 원래 ID/시점을 유지한다.

아직 기록이 입력/저장되지 않은 항목은 비어 있다. 특히 이번 작업이 새 타이머·수정/거절 UI를 추가한 것은 아니다. 기존 승인 RPC는 accepted를 저장하지만 modified/rejected가 없는 사용자는 해당 이력이 없다. 새로운 기록 UI와 항목별 실행 범위의 구조화는 별도 후속이다.

## 2. 근거 선택 개선

이전에는 개요 단원의 앞 3개, 상세 단원의 앞 4개를 주로 사용했다. 이제 요청 목표/시험 범위/마감 정보/확정 주제 및 실제 진도에서 나온 단어와 관련된 근거를 먼저 선택한다. 요청 범위와 실제 진도에 각각 제한된 검색어 예산을 둬 한쪽이 다른 쪽을 전부 밀어내지 않게 한다.

이는 국소적인 lexical retrieval이며 학습 우선순위나 시간을 계산하는 고정 학습 알고리즘이 아니다. 의미 검색/형태소 분석을 수행하는 RAG 엔진도 아니다. 동의어나 한글 조사 차이는 놓칠 수 있고, 관련성은 이후 실제 과목 평가로 확인해야 한다. 연관 근거가 없을 때는 원래 순서를 안정적으로 유지한다.

자료별 24,000자, 검색 8,000자 및 기존 항목 제한을 유지했다. 단원/목록/문자열/아티팩트가 잘리면 `context_truncated`에 반영한다. 가용/포함 아티팩트·단원 수와 선택 방식도 전달한다. 포함 비율을 전체 과목 이해도나 자신감 점수로 해석하지 않는다. 분석/검색 캐시 키는 바꾸지 않아 재분석을 유발하지 않는다.

## 3. 선택적 입력이 없어도 구체적 추천

지침에 다음을 반영했다.

- 원하는 결과/추가 요청/개인 선호/이력이 없더라도 유효한 요청에서는 계획 생성을 계속한다.
- 과목명, 실제 자료와 진도, 관측된 이해도, 마감, 가용시간으로 잠정 수준을 판단한다.
- 자료가 부족하면 일반적인 과목 지식으로 수행 가능한 구체 과업을 설계하고 가정한 수준을 짧게 밝힌다. 실제 강의 범위나 시험 유형을 지어내지 않는다.
- 모델이 만든 예제·연습은 새로 설계한 활동으로 구분한다. PDF에서 발견한 문제인 것처럼 인용하지 않는다.
- 진단 활동이 필요하면 실제 공부에 짧게 포함할 수 있지만, 기본 응답 전체를 '정보를 입력해 주세요'로 대체하지 않는다.
- 목표 난이도, 실제 수업 범위와 사용자 부족 정도, 남은 기간, 시간 예산에 맞춰 작업 범위·방법·배분을 함께 조절한다.
- 모든 과목에 개념/문제/모의고사를 전부 시키거나 고정 비율·가중치를 적용하지 않는다.
- 기존 선호보다 현재 명시적 요청을 우선한다. 단 한 번의 이행/거절로 영구 성향을 판단하지 않는다.
- 수락과 완료는 숙달 증거가 아니다. 부분 완료 시간을 완전한 과업 수행속도로 학습하지 않는다.

목표 선택·계획 기간·가용 시간대처럼 실행에 필수인 기존 입력과 인증·자료 전송 동의는 계속 필요하다. 이번 수정이 시험 준비 화면의 필수 시험 일시를 임의 추정하게 하거나 접근 오류를 무시하게 하는 것은 아니다.

## 4. 보존한 것과 바뀌는 것

유지: 사용자별 소유권 필터, 확인된 목표/주제 ID, 외부 인용 출처, 일정 충돌/이동/휴식 validator, 기존 계획 보존, 사용자 승인, 모델 종류·추론 강도·출력 상한, 기존 파일/검색 캐시.

변경: 모델에 전달하는 DB 관측과 근거 순서, 지침, 입력/지침 버전. 따라서 실제 추천 내용은 의도적으로 달라질 수 있다. 새 DB 열/테이블이나 학습 작업은 없다. 입력 스냅샷은 기존 context 구조에 새 관측을 포함하고 새 버전 마커를 남긴다.

추가 비용/부담: 목표별 실행 조회와 피드백 조회가 추가되고 개인 기록만큼 입력 토큰이 증가할 수 있다. 조회는 고정된 범위이며 새 LLM 호출을 추가하지 않는다. DB 조회가 실패하면 없는 이력인 것처럼 위장하지 않고 오류를 표시한다.

완료 기준은 기존 reason에서 구체적으로 설명하게 하고, 별도 `completion_criteria` 필드까지 채우는 출력/API/RPC 계약 변경은 이번에 하지 않았다. 전체 실행 범위 추적이나 개인 시간 추정의 통계적 보정이 이미 완성됐다고 주장하지 않는다.

## 5. 검증 및 다음 품질 확인

자동 검증 대상: 과목별 균형 조회·소유권, 피드백 관련 run 제한, 이력 조회 실패, 개인 선호·피드백·세션 ID의 실제 모델 요청 포함, 비공개 metadata 제외, 선택 입력 공란, 뒤쪽 단원의 검색/페이지 보존, 잘림 보고, 원본 아티팩트 불변, 기존 캐시 재사용과 일정·승인 회귀.

실행 결과: Node 테스트 124개, Edge 테스트 10개, 전체 Edge 타입 검사, 프런트 TypeScript 검사 통과. 실제 사용자 자료는 사용하지 않고 동일한 가상 사례 6개로 기존/개선안 총 12회 실제 `gpt-6.1-sol` 비교를 수행했다. 추천 생성과 일정 검증 모두 통과했다. 구체성·개인 피드백·뒤쪽 단원 근거 활용에서 개선 근거가 있었고, 나머지 사례는 대체로 동등했다. 비블라인드 소규모 정성 평가이지 교육 성과 검증은 아니다.

입력 토큰은 12,839 → 16,608, 총 토큰은 16,799 → 21,095로 증가했다. 새 모델 호출이나 PDF 재분석은 없지만 비용 절감 효과를 주장하지 않는다. 상세 조건·실제 응답·한계는 `docs/coaching-quality-comparison-2026-11-09.md`와 연결된 JSON에 기록했다.

이 검증은 전달/호환성 검증이다. 실제 추천이 좋아졌다는 교육적 성과 평가는 아니다. 같은 과목에서 (1) 이해도만 변경, (2) 마감만 변경, (3) 가용시간만 변경, (4) 이력 없음/있음, (5) 구체 작업을 요구한 과거 피드백 유무를 비교한다. 작업 구체성·실제 수준 적합성·범위 누락·근거·비용을 별도로 검토한다.

우선 후속: 사용자가 실제 기록을 남기기 쉬운 실행/피드백 UI → 과업 완료 범위와 기준의 구조화 → 관측 데이터가 충분한 경우 개인 시간 추정 보정. 파인튜닝이나 사용자 전체 데이터 학습은 하지 않는다.
