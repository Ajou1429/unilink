# PDF 자료 분석과 확인 등록

노트 열기에서 PDF 분석을 실행하면 사용자가 동의한 PDF를 OpenAI Responses API에 전송한다. 모델은 수업 주제, 과제, 시험의 후보와 원문 인용문·물리 페이지 번호를 제시한다. 페이지 존재 여부와 필드 길이는 서버가 검증하지만 인용문의 정확성은 사용자가 PDF와 대조해야 한다. 문서 안의 지시는 데이터로 취급한다.

## 저장 흐름

`notes → note_analyses → note_analysis_candidates → 사용자 확인 → goal_topics 또는 calendar_events`

분석은 Edge Function의 백그라운드 작업으로 실행한다. 화면은 상태를 조회하며 닫았다 열어도 이어서 확인한다. 원본 노트 버전·수정 시각, PDF SHA-256, 모델·프롬프트 버전, 페이지 수, 사용 토큰을 저장한다. 같은 버전의 완료된 결과는 재사용한다. 실패한 작업은 다시 요청할 수 있고 4분 이상 중단된 작업은 재요청 시 실패 처리한다. 내구성 있는 외부 작업 큐는 아직 사용하지 않는다.

분석 요청은 사용자별 24시간 최대 5회, 동시 1개, PDF 20MB·50페이지 이하로 제한한다. 원문 전체의 페이지별 텍스트 보관·검색은 후속 단계이며 현재는 후보별 근거 인용문과 페이지를 저장한다. 날짜의 연도·시간대를 자동 추정하지 않으며 등록할 날짜·시간은 사용자가 확인한다.

## 승인

`confirm_note_candidate`는 로그인 사용자, 후보 소유권, 현재 노트 버전·수정 시각, 활성 목표를 검증한다. 행 잠금을 사용해 중복 클릭과 재시도에도 같은 후보를 한 번만 등록한다. 수정된 자료의 이전 후보는 등록할 수 없다. 이전에 등록한 일정이나 주제는 재분석으로 덮어쓰지 않는다.

확인한 수업 주제는 `goal_topics`에 저장되어 코칭의 확정 토픽 조회에 포함된다. 과제 내용·마감과 시험 범위·일시는 `calendar_events`에 저장되어 오늘 계획·시험 대비·시간 충돌 검사에서 사용한다. 노트 삭제는 분석 기록과 후보를 함께 삭제하지만 확인된 토픽·일정을 자동 삭제하지 않는다.

## 배포

1. `0020_note_analysis.sql` 적용
2. `note-analyze` Edge Function 배포
3. 기존 `OPENAI_API_KEY` 사용. `NOTE_ANALYSIS_MODEL`이 없으면 `COACHING_MODEL`을 사용하며 PDF 입력을 지원하는 모델이어야 함
4. 노트 화면과 개인정보 안내 배포

실제 품질 검증은 개인정보 없는 PDF로 주제·과제·시험을 각각 추출해 원문 페이지와 대조한다. 모호한 날짜, 정보가 없는 문서, 스캔본, 파일 변경, 타 계정 접근, 승인 재시도, DB 오류와 모델 시간 초과를 포함한다. 자동 테스트 통과는 추출 내용의 교육적 정확성 검증을 대신하지 않는다.
