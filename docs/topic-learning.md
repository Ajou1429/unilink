# 진도와 이해도 연결

수업 페이지의 진도·이해도 탭 또는 계획 추천의 계획 전 진도·이해도 확인에서 확정 토픽별 상태를 기록한다. PDF 분석으로 확인 등록한 토픽과 사용자가 직접 추가한 토픽을 함께 사용한다. 개인 학습 목표도 회차 연결 없이 같은 상태 기록을 사용한다.

상태는 미학습·학습 중·복습 필요·이해함이다. 미입력은 미학습과 구분한다. 이해도 1~5는 자기평가이며 문제풀이 점수나 객관적인 숙련도가 아니다. 미학습에는 이해도 점수를 붙이지 않는다. 학습 완료 체크만으로 점수를 올리지 않는다.

## 저장과 코칭

`record_topic_observation` RPC는 사용자, 확정 토픽, 활성 목표, 관측 시각, 노트 소유권과 페이지 범위를 검증한다. 회차를 선택하면 같은 수업인지 확인하고 `course_session_topics` 연결을 원자적으로 추가한다. 소유자별 요청 ID를 사용해 같은 저장 요청의 재시도를 중복 기록하지 않는다.

`topic_observations`는 수정 대신 새 관측을 추가한다. `topic_learning_states`는 토픽별 가장 최근 관측 시각의 자기보고를 조회하는 보안 호출자 뷰다. 서로 다른 평가를 합산한 숙련도 추정치가 아니다. 과거 기록을 뒤늦게 입력해도 더 최근 관측을 덮어쓰지 않는다. 회차·노트가 삭제되면 연결 ID만 비우고 과거 기록은 보존한다.

계획 요청 시 서버는 선택한 목표의 현재 토픽 상태를 새로 조회해 코칭 스냅샷에 포함한다. 출처, 관측 시각, 학습 상태, 자기평가, 메모, 수업 회차, 노트와 페이지가 전달된다. 연결된 노트 본문을 읽었다고 간주하지 않는다. 계획 화면에서 상태 저장이 진행 중이면 생성 버튼을 막는다. 입력하지 않은 항목은 상태를 알 수 없는 것으로 처리한다.

## 범위와 후속 작업

이번 단계는 진도·자기평가·자료·회차 연결과 계획 입력까지다. 진단 문제 생성·자동 채점, 자기보고와 문제풀이 결과의 통합 추정, 기존 계획의 자동 변경은 포함하지 않는다. 짧은 확인 문제를 추가할 때는 별도 평가 관측 유형과 채점 근거를 도입한다.

배포 시 `0024_topic_learning_observations.sql`을 적용한 뒤 `coaching-propose`와 화면을 배포한다. 자동 검증은 사용자 분리, 다른 수업 회차 차단, 페이지 범위, 원자적 연결, 중복 방지, 과거 기록 보존과 코칭 입력 범위를 포함한다.
