# UniLink 대화형 학습 도우미와 기능 실행 연결

상태: 2026-11-16 로컬 구현. 운영 DB 변경·Edge 재배포·Git 커밋/푸시·웹 배포·새 유료 AI 호출은 이번 작업에서 수행하지 않는다. 기존 운영 DB 0038 및 이전 작업은 그대로 유지한다.

후속 운영 상태: 프로토콜 불일치 오류 요청에 따라 같은 날 `chat-record`만 v3로 배포했다(ACTIVE, JWT 검증 유지). 임시 계정의 실제 일상 대화/계획 실행 선택은 protocol 1·HTTP 200, 기존 기록 모드도 200을 확인했다. 3회 입력 합계 5,051/출력 223토큰을 사용하고 임시 계정을 삭제했다. DB/다른 서버/Git/웹은 이번 후속에도 변경하지 않았다. 아래의 ‘배포 전’ 표시는 최초 구현 시점 기록이다. 새 모드의 실제 장문 설명 품질·PDF→계획 전체 흐름은 후속 대조 대상으로 유지한다.

## 사용자 경험

- 인사·일상 대화에는 짧고 자연스럽게, 공부 질문에는 개념의 직관 → 단계 → 작은 예시 → 필요하면 확인 질문으로 답하도록 지침을 분리했다. 기존의 ‘이 채팅은 기록만 한다’ 제한은 새 대화 모드에서 제거했다. 실제 모델 답변의 친절함/정확성은 후속 실제 호출 평가가 필요하다.
- 요청한 기능은 대화 안의 실행 카드로 연결한다. 계획 생성은 기존 추천 창에 과목 목표·요청·요청 종류와 명시한 정시 단위 시간/분량 초안을 전달한다. 사용자가 가용시간·분석 동의를 확인해 생성하고, 시간표 제안을 승인하면 DB에 저장한다. 반시간 경계를 한 시간으로 넓혀 추측하지 않는다. 시험 범위/일시와 오늘 할 작업 등 필수 입력은 기존 화면에서 확인한다.
- 강의 노트와 요청을 함께 보내거나, 파일만 먼저 올리고 뒤이어 요청하면 최근 첨부의 처리 완료 후 과목/노트 메타데이터를 읽어 기능 선택에 사용한다. 실패한 첨부는 오류 상태로 전달하며 PDF를 읽었다고 표시하지 않는다. 새 채팅·계정 변경·언마운트는 대기 작업을 중단한다. 이전 첨부 취소가 새 채팅의 첨부 대기열을 지우지 않도록 구분했다.
- PDF 분석은 본인 노트 선택 → 기존 원본 미리보기/분석 패널 → 별도 전송 동의 → 후보 확인·등록 순서를 재사용한다. 이후 계획 생성의 기존 과목 지식 분석 흐름에서 자료를 활용한다. 대화 모델에는 제목/메타데이터만 전송하므로, 본문을 읽지 않은 상태에서 노트 내용 설명·요약을 했다고 주장하지 않는다.

## 실행 범위

‘실행창 연결’은 링크 문구나 가상 UI가 아니라 실제 서비스 화면을 채팅의 대화상자 안에 여는 방식이다. 모든 세부 입력/변경을 자연어 한 문장만으로 자동 완료하는 API 에이전트와는 구분한다. 사용자 요청으로 기능을 선택하고 화면에서 실제로 조회·입력·실행한다. Drive OAuth는 공급자의 임베딩 제한을 피하도록 전체 화면 열기를 제공한다.

| 기능 | 연결 방법 |
| --- | --- |
| 학습 계획 생성 | 기존 코칭 추천 컴포넌트 직접 재사용, 과목/요청/모드/명시 시간 초안 전달 |
| PDF 분석 | 본인 PDF 선택 및 기존 분석·등록 컴포넌트 직접 재사용 |
| 학습 코치 | 기존 코칭 작업 공간과 대화 설명 |
| 문제은행 | 실제 문항 등록·분석·이해도·관리 작업 공간 |
| 나의 노트·자료 검색 | 기존 노트 검색·업로드·분류·보기 작업 공간 |
| 시간표·일정 | 기존 수업 추가·월간/주간·일정 관리 작업 공간 |
| 수업·과제·시험 관리 | 요청 과목 ID를 검증해 수업 상세에 전달 |
| 개인 학습·목표 | 기존 개인 학습 작업 공간 |
| 계획 실행·완료 | 기존 학습 계획 작업 공간 |
| 오늘 계획·수업·예정 일정 | 기존 홈 작업 공간, 미루기·빠른 추가 포함 |
| 성적·스펙 / 학점 계산 | 기존 두 작업 공간 |
| Drive / 설정 | 기존 인증·동기화/설정 작업 공간 |

등록 경로는 `CHAT_FEATURES` 한 곳에서 관리한다. Pages에서는 실제 정적 `route.html`을 사용하고 로컬에서는 일반 경로를 사용한다. 모델이 임의 URL·SQL·함수 이름을 선택할 수 없고 과목·노트 ID도 제공 목록과 대조한다. 노트와 과목의 소속이 다르면 요청을 버린다. UI 실행은 로그인한 브라우저의 기존 소유권/RLS/검증·동의·승인 절차를 따른다.

## 서버 계약과 개인 정보

- 기존 `chat-record`에 `assistant_protocol: 1` 분기를 추가했다. 엄격한 JSON 스키마의 `reply/actions/tools`를 다시 검증한다. 기존 클라이언트는 종전 기록 전용 프로토콜을 유지한다. 새로운 클라이언트가 오래된 서버와 연결되면 업데이트 필요를 명확히 표시한다.
- 대화 동의는 `unilink:chat-assistant-consent:v1`로 별도 확인한다. 종전 기록 전용 동의를 확대 재사용하지 않는다. 전송 대상은 현재 메시지, 제한된 최근 대화, 과목·주제·문항 목록, 노트 제목, 본인 브라우저 일정/수동 계획 일부, 본인 승인 AI 계획 최대 8건과 최근 자기보고 이해도 최대 12건이다. 조회 실패는 기록이 없다고 표시하지 않는다. 메시지는 최대 4,000자, 모델 출력은 최대 3,500토큰이다. PDF 파일 바이트는 이 프로토콜에 포함하지 않는다.
- OpenAI `store:false` 유지. 대화 원문을 새 DB에 저장하거나 사용자 장기 성향으로 만들지 않는다. 명시한 진도/이해도는 기존 원문 비저장 기록 RPC를 이용한다. 질문·가상 예시·모델의 조언은 수행 기록이나 이해도 점수로 만들지 않도록 지시한다.
- 기능 선택은 실행 완료가 아니다. 계획 생성/저장, PDF 분석, Drive 동기화를 도구 선택만으로 성공했다고 안내하지 않는다. 수동 계획 보호와 변경 승인 원칙은 기존 하네스를 유지한다.
- 일반 대화도 기존 chat 호출 한도에 포함되며 무제한 무료 채팅으로 바꾸지 않았다. 모델 설정·요율·호출 한도는 변경하지 않았다.

설계 참고: [OpenAI 공식 function calling 안내](https://developers.openai.com/api/docs/guides/function-calling). 모델의 선택과 실제 애플리케이션 실행을 분리하고 결과·매개변수를 검증하는 원칙을 적용한다. 현재 구현은 Responses의 구조화 출력으로 실행 요청을 받아 브라우저의 기존 기능을 여는 방식이며, 별도의 서버 자율 도구 루프를 구현했다고 주장하지 않는다.

## 검증과 적용 순서

검증: 계약/위조 참조/동의 범위/이전 서버 구분/정시 시간 초안·기존 기록 호환 단위 검사, 전체 회귀, 타입·린트·정적 빌드, PC/모바일 브라우저 검사. 브라우저는 Supabase 전체를 가로채 가상 인증/API를 사용하므로 운영 쓰기나 유료 AI를 호출하지 않는다. 일반 대화·계획 과목/요청 자동 채움·실제 시간표 임베딩·손상 PDF 처리 후 요청·새 대화 초기화·가로 넘침/브라우저 오류를 검사했다. 화면 PNG는 `/tmp/unilink-chat-browser/`에 생성한다.

최종 결과: 전체 테스트 220개(새 계약/경합 8개 포함)·타입·경고 0 린트·Edge 타입·정적 빌드 통과. 개발 서버뿐 아니라 `/unilink` 경로의 정적 출력에서도 PC/모바일 검사를 통과했다. 파일만 먼저 올리고 별도 메시지로 요청하는 순서도 검사했다. 정적 출력 화면은 `/tmp/unilink-chat-static-browser/`에 생성한다. 실제 OpenAI 새 모드 품질이나 운영 사용자 계정 통합 검증을 완료한 것은 아니다.

운영 적용: 로컬 변경 검토/커밋 → `chat-record` 새 코드 배포(JWT 검증 유지) → 웹 배포 → 실제 계정으로 일반 대화·개념 설명·노트 업로드/과목 분류/계획 생성·승인/PDF 분석 대조. DB 추가 마이그레이션은 필요 없다. 이미 적용한 0037·0038이나 다른 서버를 다시 적용할 필요는 없다. 배포 전까지 실제 서버는 이 새 프로토콜을 지원하지 않는다.

## 추가할 학습 코칭 기능 제안

1. **학습 시작/마무리 체크인**: ‘지금 30분 가능’으로 할 일을 고르고 ‘절반만 했다’에서 실제 시간·수행 범위·막힌 이유를 확인해 기록한다. 계획 완료 체크를 숙달로 바꾸지 않는다. 기존 우선순위 5와 직접 연결된다.
2. **이해도 확인 질문·설명 되돌려 주기**: 개념 설명 뒤 확인 문제를 한 개씩 내고, 사용자가 자기 말로 설명한 부분의 누락을 짚는다. 자기 평가와 실제 확인 결과는 구분한다.
3. **힌트 중심 문제 풀이**: 바로 정답 대신 작은 힌트 → 다음 단계 → 필요할 때 풀이 공개. 실제 문항/페이지와 생성 예제를 구분하고, 문제은행의 현재 활동 단계를 연결한다.
4. **취약 단원 복습 제안**: 최근 관측·틀린 문제·마감·확정된 가용시간으로 복습 후보를 제시한다. 불충분한 기록만으로 고정된 망각 주기나 ‘취약’ 판정을 만들지 않는다.
5. **미완료 계획의 승인형 재계획**: ‘오늘 못 했다’에서 남은 분량과 사유를 확인하고 바뀔 일정/범위를 비교한 뒤 승인받는다. 수동 계획은 이동·축소·삭제하지 않는다.
6. **주간 회고**: 계획 대비 실제 시간·완료 범위·이해도 변화와 다음 주 조정을 짧게 정리한다. 학습 효과 향상률은 평가 근거 없이 수치로 주장하지 않는다.

우선순위는 1 → 2/3 → 5 → 4/6을 권한다. 새 관측을 실제로 수집하고 다음 추천에 연결하는 것이 현재 데이터 기반과 맞으며, 이 항목들을 이번 구현 완료로 표시하지 않는다.


## 최신 변경: 자연어 초안 → 예/아니오 확인 실행 (protocol 2)

2026-11-16 사용자 요청에 따라 쓰기 요청은 수동 입력 팝업 대신 대화에서 내용을 추출한다. 필수 값이 없으면 대화에서 질문하고, 값이 갖춰지면 실제 대상·날짜·시간·변경 내용을 표시한다. 버튼 또는 채팅의 ‘예/아니오’로 승인/취소한다. 수정 문장은 승인으로 취급하지 않고 초안을 다시 만든다. 아래 내용이 앞의 protocol 1 실행창 설명보다 우선한다. 조회 화면을 명시적으로 요청한 경우에는 기존 작업 공간을 유지한다.

- 지원 명령: 개인 일정, 과목 과제·시험, 개인 목표, 수동 계획, 수업, 성적 추가 / AI 계획 생성·승인 / PDF 분석 / 노트 분류 / 문제은행 수행 단계 변경 / 계획 완료·AI 계획 미루기 / 선택된 Drive 폴더 동기화.
- AI 계획은 입력이 충분하면 실제 미승인 추천을 만들고 시간표·완료 기준을 보여준 뒤 ‘예’에서만 저장한다. 필요한 PDF 분석이 아직 없으면 원문 OpenAI 전송 동의를 먼저 받고, 분석·생성 후 계획 저장을 따로 확인한다. 수동 계획의 자동 이동·축소·삭제 금지는 유지한다.
- PDF 분석은 명시적 확인 후 요청하며 실제 결과를 기다린다. 강의 소제목·과제·시험 후보를 표시하고 일정 등록 완료라고 주장하지 않는다. 노트 분류·문항 단계·계획 완료는 소유권과 최신 상태를 확인한다.
- 명령별 불변 초안, 5분 만료, 계정 범위/세션 확인, 새 대화 취소, 동일 확인 중복 실행 방지와 재시도 ID를 적용했다. 새 요청은 이전 미확인 초안을 대체한다. ‘아니오’는 미실행 요청을 취소하며 이미 처리된 작업을 되돌렸다고 주장하지 않는다.
- 현재 한 대화 응답당 변경 명령 하나를 처리한다. 수업 추가는 나열한 요일의 공통 시간대를 지원하며 요일별 시간이 다르면 추가 확인이 필요하다. 성적은 기존 서비스와 같이 해당 브라우저 저장이다. 삭제·계정 설정·최초 Google 인증/폴더 권한을 자동 승인하지 않는다. 파일 첨부 업로드 자체는 기존 업로드 흐름이며 이후 분석·계획 저장 승인과 구분한다.
- 일반 대화는 `assistant_protocol:2`로 `reply/actions/tools/commands`를 받으며, 허용 목록·형식·참조를 재검증한다. 이전 protocol 1과 기록 전용 요청은 서버에서 계속 지원한다. DB 구조 변경이나 대화 원문 DB 저장은 없다.

운영 `chat-record`만 v4로 배포해 ACTIVE/JWT 검증 유지를 확인했다. 임시 계정 실제 AI 호출에서 일정 초안, 후속 시간 수정 병합, protocol 1 호환을 확인했다(3회, 입력 8,065/출력 460토큰). 별도 임시 계정의 실제 DB 통합 검사에서 확인 전 취소 시 0행, 동시·반복 확인 시 과목 일정 1행을 확인했다. 두 계정과 소유 데이터를 정리했다. 이는 모든 명령과 실제 사용자 PDF→계획의 운영 통합·학습 품질 평가를 완료했다는 의미가 아니다.

검증 자료: `tests/chat-commands.test.mjs`(실제 PGlite/P0 쓰기·취소·중복·계정 변경·PDF·추천 승인), `tests/chat-assistant.browser.mjs`(가상 API로 PC/모바일 팝업 없음·대화 보완·실제 추천 표시·문자 승인·기록 승인·중복 차단). 로컬 코드와 서버 배포를 구분하며 Git 커밋·푸시 및 GitHub Pages 웹 배포는 아직 수행하지 않았다. 다음은 웹 반영과 실제 사용자 노트→계획 대조다.

최종 회귀 결과: Node 232개 전부 통과, TypeScript·경고 0 린트·webpack 정적 빌드 통과. `/unilink` 정적 출력의 PC/모바일 가상 API 브라우저 검사도 통과했으며 화면은 `/tmp/unilink-confirm-static-browser/`에 보관했다. 기존 `docs/google-login-setup.md`의 별도 미커밋 공백 변경은 이번 범위에서 수정하지 않았다.
