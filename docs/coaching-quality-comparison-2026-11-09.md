## 비교 조건과 기준

- 동일 가상 과목·노트 분석 결과·학습 기록·시간대·모델·출력 스키마·출력 상한·추론 강도. 사례별 호출 순서를 교대로 배치했다.
- 비교 대상은 모델이 아니라 **입력 구성 + 근거 선택 + 지침을 합친 시스템**이다. 새 입력에만 포함되는 기존 DB 개인 선호·피드백도 이번 변경의 일부다.
- 실제 PDF 분석이나 웹 검색을 재실행한 것이 아니다. 양쪽에 동일한 합성 분석 아티팩트를 제공하고 각 버전의 실제 `knowledgeContext`, `buildModelInput`, `generateProposal`로 요청을 구성했다.
- 생성 전에 사례와 기대 행동을 `scripts/evaluation/coaching-quality-cases.mjs`에 고정했다. 구체적 작업/완료 기준, 자료·수준 적합성, 현재 요청·시간·마감 준수, 근거 정확성을 검토했다.
- 기존 서버 validator로 보정 전·후 계획을 각각 검증했다. 인증/승인/RLS 등 회귀는 별도의 자동 테스트로 확인했다.
- 실제 사용자 데이터·Drive PDF는 전송하지 않았다. 운영 DB 조회/수정 없이 고정된 요청 해시만 허용하는 서비스 전용 임시 평가 함수를 사용하고, 비교 후 운영 함수 삭제를 확인했다. 평가 함수 코드는 커밋하지 않는다.

5. 지침 압축·빈 개인화 항목 생략·검색어/동의어 개선은 같은 품질 평가를 통과한 뒤 적용한다. 근거 삭제나 저가 모델 변경만으로 비용을 줄이지 않는다.
