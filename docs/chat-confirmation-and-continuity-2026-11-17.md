# 채팅 확인 카드와 작업 이어가기

## 표시 규칙

- 확인 카드의 제목은 과목·작업 종류의 명사형이다. 사용자 요청문, 날짜·시간이 든 문장, Markdown 제목을 복사하지 않는다. 예: `철근 콘크리트 설계 시험 일자`, `철근 콘크리트 설계 과제 마감`, `수학 계획 추천`.
- 카드에는 제목, 개조식 요약, 시간 영역을 구분한다. 시험 범위·제출 내용·장소는 요약 항목이고, 일시·마감·기간·소요 시간·순공시간·반복 요일은 하단에 표시한다.
- 필요한 입력이 모두 있고 현재 데이터로 준비한 요청만 확인 카드로 표시한다. 추가 질문·준비 중·완료·취소·오류는 일반 대화로 표시한다. 과거 실행 내역도 일반 대화로 읽는다.
- PDF 분석/계획 전 분석의 OpenAI 전송 안내와 별도 승인 절차, 임시 가용시간 안내, 수동 계획 보존, 실제 추천 시간표·완료 기준은 유지한다.

## 대화 복귀

- 대화 요청을 만들 때 같은 맥락 변환 함수를 사용한다. 원래 요청과 첨부 문서명, 최근 대화, 미확정 요청·학습 기록, 저장 결과를 전달한다. 현재 서버의 최근 6개 메시지 한도 안에서 원래 요청을 남긴다. 전체 대화를 무제한 전송하는 것은 아니다.
- 계정 소유 대화의 기존 JSON 항목에 검증한 카드 표시 정보와 선언형 미확정 입력을 추가했다. 새 DB 칼럼·마이그레이션·서버 함수 배포는 필요하지 않다.
- 미확정 일정/과제/계획 등은 명령 종류·입력 필드·요청 원문·질문을 보존한다. 학습 기록은 미확정 진도/이해도 입력과 관측 시각·중복 방지 ID를 보존한다. 실행 가능한 prepared 객체, 승인 토큰, proposal/run ID, 파일 본문, 되돌리기 권한은 보존하지 않는다.
- 대화를 다시 열면 부족한 정보를 이어서 답할 수 있다. 준비가 끝났던 요청은 ‘이전 요청 이어서 확인’으로 현재 소유권·자료·날짜를 재검증한 뒤 새 확인 카드를 표시한다. 글로 ‘예’라고 해도 처음에는 재확인만 하고 다음 명시적 승인에서 반영한다. 학습 기록도 같은 방식이다.
- 완료·취소·실행 중·실행 오류는 자동 재실행 대상으로 복원하지 않는다. 실행 중 연결이 끊겼다면 현재 데이터에서 결과를 확인해야 한다. 과거 형식의 기록은 읽기와 맥락 전달을 유지하지만 저장하지 않았던 승인 상태나 파일 본문을 복원하지 않는다.
- 계정/대화 전환 시 요청 큐와 임시 권한을 폐기하고 기존 계정의 응답이 새 화면을 바꾸지 못하게 한다. 대화 저장의 revision 충돌 검사도 유지한다.

## 검증

- 전체 Node 301개, 타입 검사·경고 0 린트·webpack 정적 빌드 및 대상 회귀 검사.
- 모든 Supabase 요청을 가로챈 PC/모바일 브라우저에서 시험 제목/개조식/하단 시각, 질문 단계 카드 미표시, 부족한 정보·승인 직전·완료 후의 재접속, 최신 재확인 후 한 번 저장, 학습 기록 재확인과 중복 방지, 과거 계획 맥락, 저장 실패 재시도, 새 대화 분리 등을 검사한다.
- 브라우저 검사와 기존 SQL 시뮬레이션은 실제 운영 사용자 데이터 쓰기나 유료 모델 호출의 증거가 아니다. 운영 DB와 웹에는 이번 변경을 아직 반영하지 않았다.
