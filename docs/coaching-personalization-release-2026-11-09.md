## 2. 기대 효과와 확인된 결과

- 확인됨: 이번 추가 요청은 현재 모델 입력에 포함되지만 새 저장용 요청 구조와 다음 빈 요청에는 복사되지 않는다. UI도 창 닫기/생성 성공 후 비운다.
- 확인됨: 만족도는 본인 제안에만 기록할 수 있고, 반복 저장 시 같은 관측을 갱신하며 삭제 후 다음 근거 조회에서 제외된다. 다른 사용자의 조회·수정은 차단한다.
- 확인됨: 만족도·자기 이해도·채점·실제 실행을 서로 다른 종류의 증거로 전달한다. 만족도가 높다는 사실을 특정 과목 숙달이나 객관적인 학습 효과로 바꾸지 않는다.
- 기대됨: 한 번 '오늘은 짧게'라고 요청한 내용이 미래의 고정 선호가 되는 오염을 줄이고, 사용자별 반복 결과를 확인할 수 있는 기반이 된다.
- 아직 미확인: 실제 사용자 추천의 질·학습 효과·만족도 상승률. 이번 변경은 무료 자동/가상 API 검증이며 새 유료 모델 대조 실험을 하지 않았다.
- 미구현: 모델 파인튜닝, 자동 개인 가중치 학습, 확정된 사용자 성향 프로파일, 실제 시간 측정/실행 기록 UI 전체, 결과 기반 재계획 전체. 기반이 생긴 것과 기능 완성을 구분한다.

## 4. 검증 결과

- Node 자동 테스트 132개, Edge 서버 시험 10개 통과.
- 프런트/서버 타입 검사, 린트, 정적 빌드 통과.
- PostgreSQL 호환 시험 DB에서 마이그레이션·트리거·소유권/RLS·점수 범위·중복 방지·수정/삭제·다음 입력 연결 확인.
- Playwright 가상 API로 PC 1365px / 모바일 390px에서 입력 초기화, 다음 요청 미재사용, localStorage 원문 없음, 평가 저장·삭제·근거 조회 확인.
- 선택 목표가 바뀔 때 이전 목표 기록을 섞지 않도록 처리. 미입력 실제 시간은 0분 대신 미기록으로 표시.
- 실사용 운영 DB, 실제 Drive PDF 내용 정확도, 실제 LLM 학습 효과는 이번 검증으로 확인했다고 주장하지 않는다.

## 5. 운영 적용에서 남은 일

main 푸시는 GitHub Pages의 **웹 화면 자동 배포**를 실행한다. 현재 워크플로는 Supabase 마이그레이션이나 Edge 서버를 자동 배포하지 않는다. 따라서 웹에 새 평가 항목이 보이는 것만으로 전체 적용 완료가 아니다. DB가 없으면 평가/근거 UI는 적용 대기로 표시된다. 기존 코칭 생성/승인 화면은 새 평가 저장과 별개로 유지된다.

1. 운영 `lqwpcwzjbqeunqfliaso`의 0029/0030 적용 여부 및 현재 코칭 함수 버전을 확인한다. 읽기 확인과 실제 변경을 구분한다.
2. 0030이 정리할 `coaching_runs.request_payload`의 대상·보존 정책을 검토한다. 기존 원문 제거는 되돌릴 수 없으므로 적용 전 정상적인 백업/승인 절차를 거친다. 시험 DB에서 적용/보존 필드를 다시 대조한다.
3. 요청·권한 범위가 확보되면 필요한 DB 변경 후 `coaching-propose`를 배포하고 웹 버전을 맞춘다. 화면이 먼저 배포된 중간 상태를 전체 완료로 보고하지 않는다.
4. 실제 계정에서 생성 → 원문 저장 제외 확인 → 승인 → 평가 저장/수정/삭제 → 다음 요청의 근거 반영까지 확인한다. 다른 사용자 접근도 확인한다.
5. 실제 반영을 확인한 뒤 개인정보 안내의 단계적 적용 문구를 확정한다. 운영 검증 결과와 서버/DB 버전을 기록한다.

이번 요청은 커밋·푸시와 정리이며, Supabase 운영 DB/서버 변경을 자동으로 포함하지 않는다.
